# jstgxmlcng_JASME — 論文 docx を J-STAGE 全文 XML に変換するツール

『全国数学教育学会誌 数学教育学研究』（J-STAGE 資料コード `jasme`）のテンプレートで作成された論文（Word の .docx）を、
J-STAGE の全文 XML（JATS 1.1、FULL-J）に変換します。

- **本文の文字は 1 文字も変えません**（誤字脱字も含めてそのまま）。変換の最後に、docx と XML の文字を 1 文字ずつ照合して確かめます。
- 受け取った docx が出版版と違うときは、先に docx を出版版 PDF に合わせて直し（Word の変更履歴つき）、それを変換することもできます
  （下の「出版版 PDF との照合と、2 通りの作り方」）。
- 見出し・本文・図表・ブロック引用・注・謝辞・付記・引用文献・英文要旨などを、テンプレートのスタイルから機械的に変換します。
- 本文中の「図1」「表2」、注の上付き番号、引用（`Claude (2025)` の **2025 の部分だけ**）、URL・DOI に機械的にリンクを付けます。
- 機械処理で取りこぼした箇所（スタイルの誤り、変則的な引用、画像で貼られた数式など）は、任意で生成 AI（Claude）に補完させられます。
  AI は文字を変更できず、提案はプログラムが検証してから反映します。AI が判断した箇所はレポートに一覧で出ます。
- 出力は J-STAGE のアップロード用フォルダ構成の ZIP と、変換レポートです。

### 複数の論文を続けて変換するとき

1 本ずつ変換します。同じ画面のまま、次のように繰り返します（手順 1 の準備はやり直さなくてかまいません）。

1. 1 本目を手順 8 まで済ませ、結果をダウンロードします。ダウンロードされるファイルの名前は論文ごとに違います
   （`変換結果_巻_開始ページ.zip`。例: `変換結果_31_1.zip`）。
2. **手順 9「続けて他の論文を変換する」の ▶ を押します。** 前の論文のファイルと入力の記録が片付き、手順 2 から始められる状態になります。
   結果をダウンロードしていないときは、一度止まって確認を求めます（もう一度 ▶ を押すと、ダウンロードせずに進みます）。
3. 手順 2 で次の論文の docx と PDF をアップロードします。
4. 手順 3 の入力欄には、**前の論文の値が残っています。** ページ・査読の有無・最終査読日・キーワード・受付日・受理日・責任著者などを、
   今回の論文のものに書き換えてから ▶ を押します（号・発行日・公開日など、同じ号で共通の値はそのままでかまいません）。
   巻と最初のページが前の論文と同じままだと止まり、キーワードや日付が前の論文と同じ値のときは注意が表示されます。
5. 手順 4（方法を変えないなら、そのまま ▶）、手順 5、（手動モードなら）手順 6、（画像が足りなければ）手順 7、手順 8 を実行します。
   手動モードでは、手順 6 の欄に前の論文の AI の回答が残っています。今回の論文の依頼文を AI に渡し、返ってきた回答に貼り替えてください
   （前の論文の回答のままだと止まります）。添付する画像も、今回の論文のもの（手順 5 でダウンロードされたもの）を使ってください。
6. J-STAGE には、論文ごとの `jasme_巻_開始ページ.zip` を 1 つずつアップロードします。

入力欄の書き換え漏れが心配なときは、手順 9 を使わずに、ノートブックを開き直して（上の「Open in Colab」のボタンから）手順 1 からやり直すほうが確実です。

そのときは手順 1 からやり直してください。

> （同じランタイムで前の版を使った後に手順 1 を実行すると、その旨が表示されて止まります）。

### AI による補完の 3 つの選び方

| 方法 | 必要なもの | 本文の送信先 | 向いている場面 |
|---|---|---|---|
| 使わない | なし | どこにも送らない | テンプレートどおりに書かれた論文（テキストボックスなどに入った図表で、位置を機械的に決められないものがあると変換できない） |
| API で自動実行（Claude・推奨） | Claude API キー（Colab の「シークレット」に `ANTHROPIC_API_KEY` として登録。作り方はノートブック手順 4 の下の「API キーについての詳細」） | Anthropic（Claude API） | 毎号まとめて処理するとき |
| API で自動実行（ChatGPT / Gemini / Sakana AI） | 各社の API キー（シークレットに `OPENAI_API_KEY` / `GEMINI_API_KEY` / `SAKANA_API_KEY` として登録）と、使うモデルの名前 | OpenAI / Google / Sakana AI | Claude の API を使えないとき |
| 手動 | claude.ai などのチャット（API キー不要） | 利用者が貼り付けたチャット | API キーがないとき、AI に渡す内容を自分で確認したいとき |

「API で自動実行」は ChatGPT（OpenAI）、Gemini（Google）、Sakana AI（Sakana Namazu・Sakana Fugu）の API にも対応していますが、**推奨は Claude です**
（AI への依頼文と動作の確認は Claude で行っています）。Claude 以外の API キーの作り方・料金・利用規約（送信した内容の扱い）は、
各社の案内を自分で調べて確かめてください。使うモデルの名前は手順 4 で自分で入力します。**Claude Opus と同等以上の性能のモデル
（各社の最上位クラスのモデル）を推奨します。** 性能の低いモデルでは、取りこぼしや誤った提案が増えます
（誤った提案はプログラムの検証で採用されませんが、補完の効果が下がります）。
**Sakana AI は、既定で送信した内容をモデルの学習に使う設定です。** 未公開の原稿を送るので、使う前に Sakana AI の管理画面（Console）の
設定で、学習への利用を止めて（オプトアウトして）ください。

手動モードでは、ツールが「AI依頼文.txt」を作ります。手順 5 の結果の先頭（とレポートの後ろ）に、依頼文が「依頼文をコピー」ボタン付きの
枠で表示されるので、チャットに貼り付け（画像があれば「AI添付画像」の画像も添付）、
返ってきた回答をノートブックの手順 6 に貼り戻すと、API モードと同じ検証・反映・最終チェックが行われます。
回答は `json` のコードブロック 1 つで返すよう依頼文で指示しているので、**コードブロック右上のコピーボタン**でコピーしてください。
コードブロックになっていない回答や、文字列が飾りの引用符（“ ”）で囲まれた回答は読み込まず、どこが読めないかを表示します
（推測で直すと AI の指示を取り違えるおそれがあるため）。その場合はチャットで出し直しを頼んでください。

### 変換レポートの見方

冒頭の「結果の要約」で、次の 3 つがすべて「合格」であることを確認してください。

1. **本文の文字の不変性チェック** — docx の全段落の文字が XML に過不足なく出力されたか（AI 補完の後に実施）
2. **最終出力の再チェック** — 作業用の目印を取り除いた最終的な XML でも文字が一致するか
3. **J-STAGE 指定 DTD による検証** — XML が J-STAGE の DTD（JATS 1.1）に適合するか

要約の「出版版 PDF との照合」に「要確認」があれば、13 章で PDF と違う箇所（「出版版 PDF に合わせてから作る」では、直した箇所と直さなかった箇所）を確認してください。
PDF を照合したときは、13 章の最後の「照合に使わなかった PDF の文字」も見てください（要約に「照合に使わなかった PDF の文字 ○ 件」、
14 章に確かめる項目が出ます）。段落の途中にあった PDF の文字のうち、組版で入る文字（誌名の行・柱・投稿受付日など）や、docx にない
図・表の中の文字（表のセルの数字、図の中の語句など）とみなして、照合に使わなかったものの一覧です（段落ごとに 1 行。表のセルの数字は
件数と最初のいくつかにまとめます。行の変わり目は「⏎」）。これらの文字は、PDF に合わせて直した docx にも入れません。表・図の中の文字や、
docx のほかの段落にすでにある文字なら、対応は要りません（「出版版 PDF に合わせてから作る」では、その文字を 13 章の「PDF に合わせて直した
箇所」で元の段落から消していないかも確かめてください）。PDF では本文なのに docx にない文字（校正で足された一文など）があったときだけ、
docx を手で直してから変換し直してください。

要約の下に「要対応」「要確認」の囲みがあれば、それぞれの対処に従ってください（14 章のチェックリストにも載ります）。たとえば次のものです。

- **要対応「XML に入らなかった画像」** — 引用文献・題目・著者名・所属の段落や、XML に出力しなかった段落（冒頭の装飾など）の中にあるため、
  XML にも ZIP にも入らなかった画像です（9 章に、画像ごとの段落と理由の推定）。Colab では赤い枠、コマンドラインでは表示と終了コード 1 でも
  知らせます。本文に必要な画像なら、Word で本文の段落に移してから変換し直してください（下の「できないこと・注意点」）。
- **要確認「テキストボックスの中の文字」「Word の文末脚注」** — 今の版では XML に出力できない文字です（6 章に全文）。本文に必要なら、
  Word でテキストボックスの外に出す、または本文の注に移してから変換し直してください。XML に出力できるようになるまでの暫定の知らせです
  （コマンドラインでも表示します）。

不変性チェックが不合格で、5 章に「変換ツールの不具合」とある（出力した段落が「出力しなかった段落」にも記録されている、など）ときは、
docx ではなくツールの誤りです。変換レポートを添えて開発者に知らせてください。

その後に、AI による補完（要確認）、機械処理で解決できなかった箇所、機械的な推定、XML に出力しなかった文字（全件）、
構造化のために落とした空白（全件）、画像、書誌情報、出版版 PDF との照合（13 章）、登載前のチェックリスト（14 章）が続きます。

## しくみ（要点）

```
docx ─読み取り→ 中間表現 ─スタイルで構造化→ ─機械的リンク→ ┬─────────────→ XML 組み立て ─ 文字の不変性チェック ─ 目印を除去 ─ 最終チェック ─ DTD 検証 ─ ZIP・レポート
                                                      └─ AI 補完（任意）: AI は「操作」の JSON を返すだけ → Python が検証して適用 ┘
```

- 段落の文字は「アトム」の列として保持し、リンクや書式は文字を包む要素として付け加えるだけにしています。文字列を書き換える処理はありません。
- 変換途中の XML では、各段落の文字を `<jx:span src="段落ID">` で囲んでおき、docx から別の実装で取り出した文字列と段落ごとに照合します。
  照合が済んでから目印を取り除き、取り除いた後の XML でもう一度文字列を照合します。
- AI に XML や docx を直接編集させることはありません。AI が返すのは「この段落のこの文字列を文献 B3 にリンクする」といった操作の一覧で、
  プログラムが 1 件ずつ検証します（存在しない文字列・リンク先、年以外へのリンクなどは不採用としてレポートに記録）。

詳しくは [docs/DESIGN.md](docs/DESIGN.md) を参照してください。

## 出版版 PDF との照合と、2 通りの作り方

受け取った docx が、著者校正を経た最終版とは限りません（組版で印刷所がかっこ・句読点を全角にそろえる、校正の直しが docx に戻されていない、など）。
手順 2 で記事の PDF をアップロードすると、docx の文字と PDF の文字を段落ごとに照合します。XML はどちらの作り方でも docx から作ります
（PDF から XML を作るのではありません。構造は docx のスタイルから決めます）。作り方は手順 2 の最初で選びます。

- **出版版 PDF に合わせてから作る**（初期値。PDF が必要）: 先に、docx の文字を PDF に合わせて直した docx
  （`巻_開始ページ_PDFに合わせた原稿.docx`）を作り、それを変換します。
  - 直すのは、英数字・記号の全角・半角（そのすぐ前後の PDF にない空白も消します。「理論 (ATD) に」→「理論（ATD）に」）と、
    それ以外の文字の違い（「資料」→「付録」など）です。直した箇所はレポートの 13 章に全件載ります。
  - 直した docx は **Word の変更履歴つき**です。スタイル・書式・数式・図・注はそのままです。Word で開いて変更を確かめ、却下したい変更が
    あれば、却下して保存した docx を「docx から作る」で変換し直してください。直した docx は、手順 8 でダウンロードする
    `変換結果_巻_開始ページ.zip` に入っています（コマンドラインでは出力フォルダ）。
  - 直さないもの: 表のセル・別行の数式・図の中の文字・資料（付録）、URL などのリンクの文字、PDF に見つからない段落、空白だけの違い
    （PDF の空白は信頼できないため）。直すと注・引用文献などのリンクや段落の役割が変わってしまう箇所も直しません（本文の「（注1）」が
    PDF では上付きの「1）」のときなど。注の番号は、すべての注で docx のままにします）。直さなかった箇所は 13 章に理由付きで載ります。
  - PDF のページ番号・誌名の行・柱（各ページに繰り返す誌名・著者名など）・投稿受付日など、組版で入る文字と、docx にない図・表の中の
    文字（表のセルの数字、図の中の点の名前など）は、段落の途中にあっても docx に足しません（PDF の側にこうした文字しかない位置の docx の
    文字も、消さず、置き換えません。13 章に理由付きで載ります）。足さなかった文字のうち、段落の途中にあったもの（ページ番号を除く）は、
    13 章の最後に一覧が載ります。ページの端の行にまるごと入った校正の一文なども、柱などと区別できないので
    ここに載ります。本文の一部なら、docx を手で直してから変換し直してください。PDF にだけある 20 文字以上の文字も、図の中の文字などの
    ことがあるので足しません（本文の行にかかるものは 13 章に理由付きで載ります）。13 章で PDF の文字の「⏎」は、PDF の行の変わり目です。
  - PDF の行末のハイフンと同じ位置にある docx のハイフン（self-explanation の「-」など）は、docx のままにします（行末で単語を分けた
    ハイフンか、本当のハイフンかを PDF から決められないため。docx にハイフンがなければ足しません）。PDF の行末の文字が、docx と違う
    「-」「‐」のとき（docx の「‑」〈Word の改行なしハイフン〉と PDF の「-」など）は、行の途中と同じく PDF に合わせて直します。
  - docx のダッシュ（en dash「–」、em dash「—」、水平線「―」、マイナス「−」など）と同じ位置に、PDF では行末の「-」があるとき
    （引用文献のページの範囲が「pp.11-」と「16」の 2 行に分かれるときなど）は、行の途中のダッシュの違いと同じく、PDF に合わせて
    「-」に直します（docx のダッシュは消しません）。PDF の行末の文字が何の字形か分からないとき（PDF の文字の取り出しで行末の
    ハイフンの印になるとき）は、docx のままにします。
  - PDF の中で表・図やほかの段落に分断された段落も、分かれた部分ごとに照合して直します。段落の最初・最後で、PDF にだけある文字を
    足すか、docx の文字を消すかを決められない違い（図の中の文字が本文の行につながっているかもしれないもの、段落の最後〈最初〉の
    文字とよく似た図の中の行と並べたかもしれないもの、PDF の同じ行に 2 つの段落が並び、間の文字がどちらの段落の文字か決められない
    ものなど）は、直さずに 13 章に理由付きで載せます。
  - PDF で数式など文字として読み取れない部分（PDF の文字では空白の並びになります）のすぐ隣にある違い（校正で足された、数式を含む
    語句など）は、足す文字を決められないので直さず、13 章に理由付きで載せます（13 章の表の「〓」は、PDF の欄では PDF の数式などの
    位置、docx の欄と前後の欄では docx の数式・画像です）。本文に
    必要なら、docx を手で直してから変換し直してください。
  - Word が付ける番号（自動段落番号、Word の脚注機能の脚注番号）は docx の文字ではないので、変換のときに全角・半角を PDF に合わせます
    （本文の注番号「1)」→「1）」、注の一覧「1)」→「１）」など）。
- **docx から作る**: docx の文字のまま XML にします。PDF と違う箇所（全角・半角の違い、「資料」と「付録」、引用符の ' と ’、
  大文字・小文字など）は、レポートの冒頭と 13 章に「要確認」として載せるだけです。PDF がまだないときや、docx が著者校正を経た最終版だと
  分かっているときに選びます。
- コマンドラインでは、`--pdf 記事.pdf` を指定すると「出版版 PDF に合わせてから作る」、指定しないと「docx から作る」になります。
  PDF を指定して「docx から作る」にするときは `--route docx` を付けます。

## できないこと・注意点

- Word の図形やグループ化した図形で描かれた図、グラフ（画像ファイルを持たないもの）は画像にできません（docx には画像ファイルがなく、Word が表示するときに描いているため）。その図の画像のファイル名が、レポートの冒頭と 14 章のチェックリスト、Colab の赤い枠に出ます。
  Colab では手順 7「足りない画像をアップロード」で、図ごとにその図の画像（記事の PDF から図の部分を切り取った画像、Word で図を右クリックして
  「図として保存」で作った画像など。PNG・JPEG、または図の部分だけの 1 ページの PDF）を選ぶと、正しい名前にして ZIP に入れ、レポートも作り直します。
  図の題目（「図1　…」）は XML に入っているので、画像には含めません。
- テキストボックスやグループ化した図形に入った図表（2 段組をまたぐ図など）は、図の本体とキャプションを組にして、
  Word で表示したときに図の左上の直上にある本文の段落の後に置きます。docx には表示後の位置が記録されていないため、位置を機械的に決められるもの
  （図の左上が、図形を結び付けた段落の左上にあるもの）以外は AI に判断させます。**そうした図表がある原稿は、AI による補完を「使わない」では変換できません**
  （手順 5 で中止し、「API で自動実行」か「手動」を選ぶよう表示します）。AI が判断した位置はレポートの 2 章と「AI判断一覧」に出ます。
  AI を使っても位置が決まらなかった図表は、図を結び付けた段落のすぐ後ろ（AI が注や引用文献などの段落の後ろと答えたときは本文の最後）に仮に置き、
  レポートの冒頭に「要対応」として出します。XML の中で手作業で正しい位置に移してください。
  表のセルに画像とキャプションを並べた図や、画像のない図キャプションのすぐ上に置いた表（表で組んだ図）は、AI を使わなくても図として組みます。
- 引用文献・題目・著者名・所属の段落には、画像を出力できません。こうした段落や、XML に出力しなかった段落（冒頭の装飾など）の中に
  画像があると、その画像は XML にも ZIP にも入りません。レポートの冒頭（要対応）・9 章・14 章、Colab の赤い枠、コマンドラインの表示に
  「XML に入らなかった画像」として出るので、本文に必要な画像なら、Word でその画像（テキストボックスなどの図形に入っているときは図形ごと）を
  本文の段落に移してから、変換し直してください。隠し文字の中の画像は、Word で表示されないので出力しません（レポートの 6 章に記録します）。
- 図・表を含まないテキストボックス（囲み）の文字と、Word の文末脚注は、今の版では XML に出力できません（レポートの 6 章に全文が載ります）。
  あるときはレポートの冒頭と 14 章に「要確認」として出るので、問題文などの囲みなら Word でテキストボックスの外（本文の段落）に出し、
  文末脚注なら本文の注（テンプレートの書き方）に移してから、変換し直してください。
- EMF/WMF の図は LibreOffice で PNG に変換します（Colab では手順 1 で自動インストール）。
- ルビ（ふりがな）は JATS 1.1 で表現できないため、親文字だけを出力します（レポートに記録）。
- 和文の論文の英文要旨は、J-STAGE の規則（「抄録(英)」には「タイトル(英)」が必要）に合わせて翻訳抄録（`<trans-abstract>`）として出力します。
  抄録の二次利用の可否（`specific-use`）は `<abstract>` にしか付けられないため、和文の論文では出力されません。
  英文の論文で使う値は `src/jasme_jats/data/jasme.toml` で設定してください（既定は「二次利用不可」）。
- DTD に合っていても J-STAGE のアップロードで弾かれる条件のうち、XML だけで判定できるもの（題目と抄録の言語の対応など）は変換時に確かめ、レポートの 12 章に出します。
- 注はテンプレートの書き方（本文に上付きの「1)」、注は「注」の節）を想定しています。本文の大きさの「（注1）」や、引用文献の後ろに置いた注の節も変換できます。Word の脚注機能で書かれた注は、番号を本誌の形式「1)」にし（Word の表示は「1」）、見出し「注」を補います（どれもレポートの 4 章に記録します）。番号の書き方が想定外の注は 1 件にまとめられることがあるので、レポートの 3 章を確認してください（AI による補完で区切りを直せます）。
- 図表番号は既定で `<caption>` の中に番号ごと入れます（文字を落とさないため）。`<label>` に分けたい場合はノートブックの `SPLIT_LABELS` をオンにします（番号とタイトルの間の空白 1 文字を落とし、レポートに全件記録します）。

## ローカル（パソコン）で使う場合

Python 3.10 以上が必要です。

```bash
pip install "jasme-jats[ai,images] @ git+https://github.com/thjpme/jstgxmlcng_JASME.git@main"
python -m jasme_jats 論文.docx --meta 書誌情報.toml --out output            # AI を使わない
python -m jasme_jats 論文.docx --meta 書誌情報.toml --out output --ai manual  # 手動モード（依頼文を作る）
python -m jasme_jats 論文.docx --meta 書誌情報.toml --out output --ai manual --ai-response 回答.json
ANTHROPIC_API_KEY=... python -m jasme_jats 論文.docx --meta 書誌情報.toml --out output --ai api
OPENAI_API_KEY=... python -m jasme_jats 論文.docx --meta 書誌情報.toml --out output --ai api --ai-provider openai --ai-model モデル名
GEMINI_API_KEY=... python -m jasme_jats 論文.docx --meta 書誌情報.toml --out output --ai api --ai-provider gemini --ai-model モデル名
SAKANA_API_KEY=... python -m jasme_jats 論文.docx --meta 書誌情報.toml --out output --ai api --ai-provider sakana --ai-model モデル名
python -m jasme_jats 論文.docx --meta 書誌情報.toml --out output --images 画像フォルダ   # 用意できなかった図の画像（25_77_01.png など）を入れる
python -m jasme_jats 論文.docx --meta 書誌情報.toml --out output --pdf 記事.pdf               # 出版版 PDF に合わせてから作る
python -m jasme_jats 論文.docx --meta 書誌情報.toml --out output --pdf 記事.pdf --route docx  # docx から作る（PDF とは照合だけ）
```

書誌情報ファイルの例: [examples/meta_example.toml](examples/meta_example.toml)
