# jstgxmlcng_JASME — 論文 docx を J-STAGE 全文 XML に変換するツール

『全国数学教育学会誌 数学教育学研究』（J-STAGE 資料コード `jasme`）のテンプレートで作成された論文（Word の .docx）を、
J-STAGE の全文 XML（JATS 1.1、FULL-J）に変換します。

- **本文の文字は 1 文字も変えません**（誤字脱字も含めてそのまま）。変換の最後に、docx と XML の文字を 1 文字ずつ照合して確かめます。
- 見出し・本文・図表・ブロック引用・注・謝辞・付記・引用文献・英文要旨などを、テンプレートのスタイルから機械的に変換します。
- 本文中の「図1」「表2」、注の上付き番号、引用（`Claude (2025)` の **2025 の部分だけ**）、URL・DOI に機械的にリンクを付けます。
- 機械処理で取りこぼした箇所（スタイルの誤り、変則的な引用、画像で貼られた数式など）は、任意で生成 AI（Claude）に補完させられます。
  AI は文字を変更できず、提案はプログラムが検証してから反映します。AI が判断した箇所はレポートに一覧で出ます。
- 出力は J-STAGE のアップロード用フォルダ構成の ZIP と、変換レポートです。

## 使い方（Google Colab。パソコンへのインストールは不要）

[![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/thjpme/jstgxmlcng_JASME/blob/main/notebooks/JASME_docx_to_JSTAGE_XML.ipynb)

1. 上のボタンからノートブックを開きます（Google アカウントが必要）。
2. 上から順に、各セルの ▶ を押します（前の手順を飛ばすと「先に手順 ○ を実行してください」と表示されて止まります）。
   1. 準備（最初に 1 回。1 分ほど）。ツールの版が表示されます。LibreOffice（EMF/WMF の図の変換用）は裏でインストールされるので、
      終わるのを待たずに次へ進めます。準備の ▶ を押した後に手順 2 の ▶ も押しておくと、準備が終わりしだい続けて実行されます
   2. 論文の docx と PDF をアップロード（docx 用・PDF 用のボタンが順に出ます）
   3. 巻・号・ページ・査読の有無（必須）・キーワード（任意。日本語・英語を別の欄に「;」区切り）・日付・原稿種別（選択）を入力
   4. AI による補完の方法を選ぶ（使わない / API で自動実行 / 手動。初期値は手動）
   5. 変換を実行 → 画面に変換レポートが表示されます
   6. （手動モードのときだけ）AI の回答を貼り付けて再変換
   7. 結果（変換結果.zip）をダウンロード
3. J-STAGE の編集登載システムで、その号の巻・号と**セクション**（目次の見出し。例: 論文）を作成しておきます
   （ないとアップロード時に「学会誌別セクションが存在しません」というエラーになります）。
4. ダウンロードした中の `jasme.zip` を編集登載システムにアップロードし、記事をセクションに振り分けて、プレビューで確認します。
   **J-STAGE では PDF が必須です。** 手順 2 で PDF をアップロードすると ZIP に入ります。

> ツールが新しくなったときは、メニューの「ランタイム」→「セッションを再起動」を選んでから手順 1 からやり直してください
> （同じランタイムで前の版を使った後に手順 1 を実行すると、その旨が表示されて止まります）。
> 開発中の版を試すときは、手順 1 の「USE_DEV_VERSION」にチェックを入れて実行し、表示される欄にブランチ名を入力します。

### AI による補完の 3 つの選び方

| 方法 | 必要なもの | 本文の送信先 | 向いている場面 |
|---|---|---|---|
| 使わない | なし | どこにも送らない | テンプレートどおりに書かれた論文 |
| API で自動実行 | Claude API キー（Colab の「シークレット」に `ANTHROPIC_API_KEY` として登録。作り方はノートブック手順 4 の下の「API キーについての詳細」） | Anthropic（Claude API） | 毎号まとめて処理するとき |
| 手動 | claude.ai などのチャット（API キー不要） | 利用者が貼り付けたチャット | API キーがないとき、AI に渡す内容を自分で確認したいとき |

手動モードでは、ツールが「AI依頼文.txt」を作ります。手順 5 の結果の先頭（とレポートの後ろ）に、依頼文が「依頼文をコピー」ボタン付きの
枠で表示されるので、チャットに貼り付け（画像があれば「AI添付画像」の画像も添付）、
返ってきた回答をノートブックの手順 6 に貼り戻すと、API モードと同じ検証・反映・最終チェックが行われます。
回答は `json` のコードブロック 1 つで返すよう依頼文で指示しているので、**コードブロック右上のコピーボタン**でコピーしてください。
コードブロックになっていない回答や、文字列が飾りの引用符（“ ”）で囲まれた回答は読み込まず、どこが読めないかを表示します
（推測で直すと AI の指示を取り違えるおそれがあるため）。その場合はチャットで出し直しを頼んでください。

### 出力されるもの

| ファイル | 内容 |
|---|---|
| `jasme.zip` | J-STAGE にアップロードするもの（`jasme/巻/号/巻_開始ページ/` の下に XML・PDF・`Graphics/` の画像） |
| `巻_開始ページ.xml` | 同じ XML（確認用） |
| `巻_開始ページ_変換レポート.md` | 変換レポート（下記） |
| `巻_開始ページ_AI判断一覧.md` | AI が判断した箇所だけの一覧（AI を使ったとき） |
| `AI依頼文.txt`, `AI添付画像/` | 手動モードで AI に渡す依頼文と画像 |
| `要変換/` | 自動で変換できなかった画像（EMF など）。PNG にして `Graphics/` に入れる |

### 変換レポートの見方

冒頭の「結果の要約」で、次の 3 つがすべて「合格」であることを確認してください。

1. **本文の文字の不変性チェック** — docx の全段落の文字が XML に過不足なく出力されたか（AI 補完の後に実施）
2. **最終出力の再チェック** — 作業用の目印を取り除いた最終的な XML でも文字が一致するか
3. **J-STAGE 指定 DTD による検証** — XML が J-STAGE の DTD（JATS 1.1）に適合するか

その後に、AI による補完（要確認）、機械処理で解決できなかった箇所、機械的な推定、XML に出力しなかった文字（全件）、
構造化のために落とした空白（全件）、画像、書誌情報、登載前のチェックリストが続きます。

## しくみ（要点）

```
docx ─読み取り→ 中間表現 ─スタイルで構造化→ ─機械的リンク→ ┬─────────────→ XML 組み立て ─ 文字の不変性チェック ─ 目印を除去 ─ 最終チェック ─ DTD 検証 ─ ZIP・レポート
                                                      └─ AI 補完（任意）: AI は「操作」の JSON を返すだけ → Python が検証して適用 ┘
```

- 段落の文字は「アトム」の列として保持し、リンクや書式は文字を包む要素として付け加えるだけにしています。文字列を書き換える処理はありません。
- 変換途中の XML では、各段落の文字を `<jx:span src="段落ID">` で囲んでおき、docx から別の実装で取り出した文字列と段落ごとに照合します。
  照合が済んでから目印を取り除き、取り除いた後の XML でもう一度文字列を照合します。
- AI に XML や docx を直接編集させることはありません。AI が返すのは「この段落のこの文字列を文献 B3 にリンクする」といった操作の一覧で、
  プログラムが 1 件ずつ検証します（存在しない文字列・リンク先、年以外へのリンクなどは不採用としてレポートに記録）。

詳しくは [docs/DESIGN.md](docs/DESIGN.md) を参照してください。

## できないこと・注意点

- Word の図形やグループ化した図形で描かれた図、グラフ（画像ファイルを持たないもの）は画像にできません。レポートの指示に従って画像を用意してください。
- テキストボックスやグループ化した図形の中に図（画像・表）とキャプションを一緒に入れた配置は、図として組になりません（文字はすべて出力されますが、図はキャプションだけ、表はキャプションなしになります。レポートの 4 章に出ます）。
- EMF/WMF の図は LibreOffice で PNG に変換します（Colab では手順 1 で自動インストール）。
- ルビ（ふりがな）は JATS 1.1 で表現できないため、親文字だけを出力します（レポートに記録）。
- 和文の論文の英文要旨は、J-STAGE の規則（「抄録(英)」には「タイトル(英)」が必要）に合わせて翻訳抄録（`<trans-abstract>`）として出力します。
  抄録の二次利用の可否（`specific-use`）は `<abstract>` にしか付けられないため、和文の論文では出力されません。
  英文の論文で使う値は `src/jasme_jats/data/jasme.toml` で設定してください（既定は「二次利用不可」）。
- DTD に合っていても J-STAGE のアップロードで弾かれる条件のうち、XML だけで判定できるもの（題目と抄録の言語の対応など）は変換時に確かめ、レポートの 12 章に出します。
- 図表番号は既定で `<caption>` の中に番号ごと入れます（文字を落とさないため）。`<label>` に分けたい場合はノートブックの `SPLIT_LABELS` をオンにします（番号とタイトルの間の空白 1 文字を落とし、レポートに全件記録します）。

## ローカル（パソコン）で使う場合

Python 3.10 以上が必要です。

```bash
pip install "jasme-jats[ai,images] @ git+https://github.com/thjpme/jstgxmlcng_JASME.git"
python -m jasme_jats 論文.docx --meta 書誌情報.toml --out output            # AI を使わない
python -m jasme_jats 論文.docx --meta 書誌情報.toml --out output --ai manual  # 手動モード（依頼文を作る）
python -m jasme_jats 論文.docx --meta 書誌情報.toml --out output --ai manual --ai-response 回答.json
ANTHROPIC_API_KEY=... python -m jasme_jats 論文.docx --meta 書誌情報.toml --out output --ai api
```

書誌情報ファイルの例: [examples/meta_example.toml](examples/meta_example.toml)
