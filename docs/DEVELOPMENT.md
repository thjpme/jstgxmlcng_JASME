# 開発者向け（引き継ぎ用）

## 環境

```bash
git clone -b main https://github.com/thjpme/jstgxmlcng_JASME.git
cd jstgxmlcng_JASME
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
python -m pytest
```

EMF/WMF 画像の変換を試すには LibreOffice（`soffice`）が必要（なければ該当テストは「変換失敗」を期待して通る）。

## コードの構成（`src/jasme_jats/`）

| ファイル | 役割 |
|---|---|
| `ooxml.py` | docx の低水準処理。**文字ポリシー**（何を docx の文字とみなすか）と、検証用の独立した文字列取り出し `canonical_text()` |
| `docx_reader.py` | docx → 中間表現（`model.py` の `Document` / `Para` / `Atom`）。コンテンツコントロール（`w:sdt`）・`w:customXml` に包まれた表の行・セル、テキストボックスの段落・表も、文書の順にたどって読む（`_children()`） |
| `numbering.py` | Word の自動段落番号を表示どおりの文字列にする |
| `omml.py` | Word の数式（OMML）→ MathML 2.0 |
| `structure.py` | 段落の役割の決定と論文の構造（`ArticlePlan`）の組み立て。出力しない段落の記録（`ArticlePlan.exclude()`、空白だけの段落は `exclude_blank()`） |
| `linker.py` | 図・表・数式・注・URL・DOI の機械的リンク、アトムにリンクを付ける共通関数 `apply_span()` |
| `refparse.py` | 引用文献の解析と著者・年方式の引用の抽出・照合（先行ツール「文献チェック」refcheck.py から移植） |
| `ai_assist.py` | AI 補完（依頼文の作成、API 呼び出し（Claude・ChatGPT・Gemini・Sakana AI）、回答の検証と適用） |
| `emit.py` / `builder.py` | XML の組み立て（文字は必ず `jx:span` の中に書く） |
| `tracking.py` | 変換途中の目印の定義 |
| `fidelity.py` | 文字の不変性チェック（出力した段落が除外にも記録されていないか、空白だけとした除外が本当に空白だけか、も確かめる） |
| `validate.py` | DTD 検証（`dtd/` に J-STAGE 指定 DTD を同梱） |
| `floats.py` | 浮動配置の図形（テキストボックス・グループ図形）の位置: 機械的に配置できるかの判定、AI に渡す位置の説明と行数の推定 |
| `pdfmatch.py` | 出版版 PDF との照合（段落ごとの対応付けと、全角・半角の違い・それ以外の違い・Word が付ける番号の違いの一覧）。PDF のページ番号・誌名の行・柱・投稿受付日など（組版で入る文字）と、docx にない図・表の中の文字は照合に使わず、段落の途中にあったものを一覧にする（`pdf_stream()`、`PdfCheck.ignored_lines`）。ページの途中の数字だけの行（引用文献の「pp.11-」の後の「16」のような前の行の続きを除く）・何ページにも出る行は、照合する列から除き、行全体でしか docx の文字と一致させない（`PdfStream.line_only`）。段落ごとの PDF の窓は、全段落を docx の順につないでまとめて照合して決める（`_joint`。0.21.0。PDF の中で表・図・ほかの段落に分断された段落も照合する）。docx に足すか・docx の文字を消すか決められない違いは、理由付きで直さない（`TextDiff.why`。`EDGE_WHY`・`UNSURE_WHY`・`WHOLE_WHY`・`LONG_WHY`・`DISPLACED_WHY`・`FAR_WHY`〈分断された段落の本体から離れた最初・最後の部分。`_isolate`。0.21.1〉・`HEAD_WHY`・`MATH_WHY`〈文字として取り出せない数式の位置。`PdfStream.formula`〉）。docx のダッシュ（en dash・em dash など）と同じ位置の PDF の行末の「-」は、PDF に合わせて「-」に直す（`DASHES`。docx のハイフンの仲間〈`HYPHENS`。「‐」、Word の改行なしハイフン「‑」など〉と、PDF の行末の docx と違う「-」「‐」も、行の途中と同じく PDF に合わせる） |
| `pdfdocx.py` | ルート2: 出版版 PDF に合わせて直した docx（Word の変更履歴つき）を作る。書き込んだ後に文字列と構造を確かめる |
| `jstage_rules.py` | J-STAGE のアップロード時チェック（記事アップロードメッセージ一覧）のうち XML だけで判定できるものの再現 |
| `images.py` / `package.py` / `report.py` | 画像の書き出し、ZIP、レポート |
| `pipeline.py` / `cli.py` | 全体の流れ（画像の出力漏れの検出 `lost_images()` を含む）とコマンドライン |
| `colab.py` | Colab ノートブックの表示部品（手動モードの依頼文の枠、XML に入らなかった画像などの赤い枠）と、続けて変換するときの入力の確認 |
| `data/jasme.toml` | 本誌の設定（誌名・ISSN・DOI 形式・スタイル名の対応表など） |

## 守るべき原則

1. **文字列を書き換えるコードを書かない。** 構造はアトムに `LinkSpec` を付けるか、段落の役割を変えることで表す。
2. XML に段落の文字を書くときは必ず `Emitter.span()` を通す（`jx:span` で囲まれない文字は不変性チェックで「追加」とみなされる）。
3. 出力しない段落は `plan.exclude()` か `BuildInfo.exclusions` に理由付きで記録する（記録しないと「出力漏れ」になる）。
   空白だけの段落（全角空白だけのものも）は `plan.exclude_blank()` で記録する（不変性チェックが、docx の文字が本当に空白だけかを確かめる）。
   出力した段落を除外にも記録すると、不変性チェックは不合格になる。
   不変性チェックは文字しか見ないので、画像は、変換の後に `pipeline.lost_images()` が、docx の画像のうち XML に出力しなかったもの
   （引用文献など画像を出力できない段落や、除外した段落の中の画像）を調べ、要対応として知らせる（隠し文字の中の画像を除く）。
4. 構造の区切りとして空白を落とす場合は `Emitter.drop()` を使う（空白以外は落とせない）。
5. 新しい種類の docx の要素に対応するときは、`ooxml.canonical_text()`（検証側）と `docx_reader.py`（変換側）の両方を同じ文字ポリシーで直し、
   その要素を含む docx を `tests/make_fixtures.py` に加えてテストする。
6. 出版版 PDF に合わせるときは、XML ではなく docx を直す（ルート2。`pdfdocx.py`、`docs/DESIGN.md` の 4.4）。直した docx は Word の
   変更履歴つきで利用者が確かめられ、それを変換する処理はルート1 と同じなので、1.〜5. はそのまま当てはまる。`pdfdocx.py` を直すときは、
   書き込んだ後の確かめ（読み直した文字列と、段落の役割・リンク・注の区切り）を外さないこと。PDF の組版で入る文字（ページ番号・
   誌名の行・柱・投稿受付日など）と、docx にない図・表の中の文字は docx に足さない（`pdfmatch.pdf_stream()` の印で照合に使わず、
   足さなかった文字はレポートの 13 章に載せる）。docx に足すか・docx の文字を消すかを PDF から決められない違い（分断された段落の端、
   数式など文字として読み取れない部分の隣など）は、足す・消す側に倒さず、理由（`TextDiff.why`）を付けて直さずに 13 章に出す。

### 実際の論文でのテスト

実際の論文（未公開原稿や著作権のあるもの）は **公開リポジトリに入れない**。`tests/private/`（`.gitignore` 済み）に置いて手元で試す:

```bash
python -m jasme_jats tests/private/論文.docx --meta examples/meta_example.toml --out output
```

出版版 PDF（J-STAGE で公開済みのものも）も `tests/private/`（例: `tests/private/pdf/`）に置く。PDF の組版で入る文字（ページ番号・
誌名の行・柱・投稿受付日。`docs/DESIGN.md` の 4.4）の扱いを確かめるときは、`pdf_stream()` が投稿受付日などとみなした文字と、
柱の候補の行（ページの端の行など。どの段落にも当たらなければ照合に使わない）を出して、ページ番号が除かれていること、本文の行が
柱の候補として除かれすぎていないことを見る:

```bash
python -c "
import sys
from jasme_jats.pdfmatch import extract_pages, pdf_stream
st = pdf_stream(extract_pages(sys.argv[1]))
print('投稿受付日など:', st.dates)
print(*dict.fromkeys(st.lines[st.line[k]] for k in range(len(st.chars)) if st.head[k]), sep='\n')   # 柱の候補の行
print('行全体でしか一致させない行:', list(dict.fromkeys(st.lines[st.line[k]] for k in range(len(st.chars)) if st.line_only[k])))
" tests/private/pdf/記事.pdf
```

docx と組にして確かめるときは、`--pdf` を付けて（ルート2）変換し、レポートの 13.1（直した箇所に、ページ番号・受付日を足したもの、

## Colab ノートブック

`notebooks/JASME_docx_to_JSTAGE_XML.ipynb` は `tools/make_notebook.py` で生成している。ノートブックを直すときはこのスクリプトを直して
`python tools/make_notebook.py` を実行する。ノートブックは実行のたびに GitHub の `main` ブランチ（手順 1 の `BRANCH`）からツールを入れる。

- 手順 1 はツール本体を毎回入れ直す（同じ版番号でもコードが新しくなるように）。同じランタイムで前の版を読み込んだ後だと
  入れ直しが反映されないため、その場合はセッションの再起動を求めて止まる。
- LibreOffice は手順 1 で裏でインストールし（`LO_PROC`）、手順 5 で終わるのを待つ。ツール本体の pip は確実さを優先して手順 1 の中で済ませる。
- 開発版は手順 1 の `USE_DEV_VERSION` にチェックを入れると `input()` でブランチ名を尋ねる（通常の利用者が誤って変えないように）。
- 手順 7 は、画像を用意できなかった図（`report.images_to_prepare`）の画像を図ごとにアップロードさせ、`pipeline.add_images()` で
  正しい名前にして Graphics/ に入れ、ZIP とレポートを作り直す。受け取った画像は `USER_IMAGES` に残し、手順 5・6 で変換をやり直したときに
  入れ直す（手順 2 で論文を選び直すと捨てる）。手順 8（ダウンロード）は、足りない画像が残っていれば一度止めて手順 7 を案内する。
- 手順 9 は、続けて他の論文を変換するための片付け（`DONE = {1}` に戻し、前の論文を `PREVIOUS` に記録する）。手順 3 は `PREVIOUS` と
  比べて書き換え忘れを知らせ（`colab.same_first_page()` / `carried_over()`）、手順 6 は前の論文の AI の回答が残っていれば止まる。
- 手動モードの依頼文の表示（コピーボタン付きの枠）とエラーの枠は `src/jasme_jats/colab.py`。手順 5・6 では、画像を用意できなかった図
  （`missing_images_box`）と XML に入らなかった画像（`lost_images_box`）を、レポートの前に赤い枠で出す（手順 8 でも、ダウンロードの後に
  もう一度出す）。
- Colab ではどのセルも押せてしまうため、各手順の最初で前の手順が済んでいるかを確かめる（変数 `DONE`）。
  ある手順をやり直すと、それより後の手順は未実行に戻る。

### J-STAGE の試験登載で分かったこと（2026-10）

詳細は `docs/JSTAGE_NOTES.md`。要点:

- 和文の論文の英文要旨は `<trans-abstract>` にする（`<abstract xml:lang="en">` だと EMSGM102E「タイトル(英)がない」）。
- アップロードの前に、編集登載システムで巻・号・セクションを作っておく（ないと EMSGM181E / EMSGM182E）。
- 注（`<fn>`）の `<label>` は表示されない。番号は `<p>` の先頭に書く。
- 引用文献の DOI を `<pub-id>` に書くと、プレビューではリンクにならなかった（設定 `ref_doi` で `<uri>` に切り替えられる）。
- アップロードする ZIP の名前は `jasme.zip` でなくてもよい（`jasme_巻_開始ページ.zip` で受け付けられた）。確かめられるのは中のフォルダ構成。
