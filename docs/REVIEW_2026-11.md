# 点検の結果（2026-11-03。0.28.1）

コード全体（`src/jasme_jats/`、`tools/`、テストの基盤、CI）を読み直し、見つけた問題を「どの程度直すべきか」で分類した。
構造の説明は `docs/ARCHITECTURE.md`。ここに挙げたものは、この点検ではコードを直していない（文書の食い違いだけ直した。末尾）。

## 確かめ方

- 対象の版: 0.28.1（`main` 6b8de22）。`python -m pytest -q` は 1136 件すべて合格。LibreOffice・pypdfium2 あり。
- 5 つの担当（読み取りと文字ポリシー／構造とリンク／PDF との照合とルート2／AI 補完と XML の組み立て／出力・画面・ツール）に分けて精読し、
  問題はすべて小さな docx や回答の JSON を作って再現した。S1・S2 のものは、別の担当がもう一度実行して確かめた
  （再現スクリプトは手元の作業フォルダにあり、リポジトリには入れていない。直すときは、ここに書いた入力の形から
  `tests/make_fixtures.py` の部品でテストを作る）。
- 「未確認（推測）」と書いたものは、コードを読んで分かる範囲で、再現していない。

## 分類

| 分類 | 意味 | 件数 |
|---|---|---|
| **S1** | すぐ直すべき。文字が docx と違う形で入る・落ちる、利用者のファイルが壊れる、例外で変換が止まる | 6 |
| **S2** | 直すべき。XML か知らせが誤る（不変性チェックで止まるが利用者に理由が伝わらないものを含む） | 14 |
| **S3** | 直したほうがよい。まれな入力での不整合、文言、保守性 | 32 |
| **S4** | 記録にとどめる。設計上の限界、Word で未確認の形、文書に既に書かれている限界 | 14 |

不変性チェック（`fidelity.verify`）が最後の守りになっているので、S1・S2 の多くは「黙って通る」のではなく
「要対応『変換ツールの不具合の可能性』で止まる」形で現れる。利用者には直し方が伝わらないので、直すべきものとして分類した。

## 詳細

### S1

**K1. 後付けの見出しが同じ種類で 2 つあると、先の見出しが出力も除外もされない**
`structure.build_back` が `plan.notes = BackSec(heading=b)` / `plan.ack` / `plan.fn_heading` / `plan.ref_heading` を無条件に上書きする。
「引用文献」と「参考文献」を別の節にした原稿では先の「引用文献」の見出しが、「付記」「謝辞」が 2 回あるときは先の節の段落がすべて、
XML にも除外の記録にも入らない。再現: `make_article()` の `refs` で「参考文献」の見出しと文献を足す →
`fidelity.missing=[('d13', '引用および参考文献')]`、要対応「変換ツールの不具合の可能性」。
直し方の案: 2 つ目以降は前の節に続ける（見出しの段落は前の節の段落として出し、判断の一覧に記録する）か、要確認で知らせる。

**K2. 所属だけの段落・行が続くと、前の所属と最後の所属が落ちる**
`author_paragraph_ja` の `self._loose_affs = [p]` が前の所属を捨て、著者が続かない最後の所属は誰にも付かない。著者表でも
`current_affs = row_affs` で前の行の所属を捨てる。所属が 2 つある著者を所属 2 行＋著者 1 行で書いた原稿で起きる。
再現: 著者表に「第二大学／（空）」の行を足す → `missing=[('d6', '第二大学')]`。直し方の案: 所属は著者が現れるまでためて全部付け、
著者のない所属は除外に記録して要確認にする。

**P1. 全角・半角の直しが止められても、隣の空白の削除だけが残る**
`drops`（全角・半角を直す文字のすぐ隣の半角空白）は、その `width` の Fix が後段で直さないことになっても `space` の Fix として直される。
経路は 3 つ: (a) 構造の確かめ（`_lost` → `_protect`）で `width` が `STRUCTURE_REASON` になる、(b) `width` の文字がほかの作成者の
`w:ins` やフィールドの結果の中で直せない、(c) 注の番号を守る `NOTE_REASON`。結果は「本文 (挿入の文字) の後ろ」→「本文(挿入の文字)の後ろ」で、
docx とも PDF とも違う。`verify_supplement` が `UNIT_WHY` で不合格にするので黙っては通らないが、利用者には原因の分からない要対応になる。
CLAUDE.md の「(A) の直しは typeset_pair の対と drops を超えて文字を変えない」に反する。直し方の案: `plan_fixes` で `space` の Fix を根拠の
`width`／番号の Fix と同じ `group` にする（group の一部が直せなければ全部直さない仕組みに乗る）。

**P2. 入力の docx が出力の「…_PDFで補完した原稿.docx」と同じパスだと入力を壊す**
`write_fixed_docx` が `src_path` を読みながら同じ `dst_path` を `ZipFile(dst, "w")` で開くため、入力が 22 バイトに切り詰められてから
`BadZipFile` で止まる。利用者が補った docx を却下して保存し、同じ出力フォルダでルート2 をかけ直すと起きる。
直し方の案: `pipeline.convert` で `docx_path.resolve() == fixed.resolve()` なら別名にするか中止する。

**A1. AI の回答の項目の型が違うと TypeError で変換が止まる**
`split_ops` は `occurrence` 以外の型を確かめないので、`src`・`target`・`role`・`image`・`after`・`caption`/`body` の要素が一覧や辞書だと
`unhashable type`、`text` が数値（`"text": 2001` は現実的）だと `normalize()` の TypeError になり、`pipeline.convert` は捕まえない。
手動モード（チャットの貼り付け）と Sakana AI のスキーマなしの再試行で起こりうる。レポートも XML も出ない。
直し方の案: `split_ops` で 12 項目を文字列に正規化し、placements も `_placement_problem` の先頭で型を確かめて不採用にする。

**A2. `notes` が一覧でないと例外**
`pipeline.py:373` の `[str(n) for n in data.get("notes", [])]`。整数なら `'int' object is not iterable` で中止、文字列なら
`['気', 'づ', 'き']` のように 1 文字ずつの気づきになる。`parse_response` で型を確かめる。

### S2

**R1. 削除の変更履歴の中のテキストボックス**: `w:del` の中の `w:r` にテキストボックスがあり、中の段落の文字が `w:t` のままだと、
読み取りは図形ごと飛ばし（Word で承諾すると消える。正しい）、検証（`paragraph_ids` はすべての `w:p` を数える）は `missing` にする。
要対応「変換ツールの不具合の可能性」の誤報。Word がこの形で書くかは未確認（`make_fixtures.deleted()` のように中の `w:t` まで
`w:delText` にする形なら一致する）。直すなら `canonical_texts` でも削除のランの中の `w:txbxContent` の段落を欠番にする。

**R2. 根号の `degHide`**: `h_rad` は `hide or not deg_items` で `msqrt` にして `m:deg` の文字を捨てる。`canonical_text` は「3x」、
`math_plain` は「x」→ 不合格。`h_nary` の `subHide`/`supHide` は「文字を落とさない」方針なので、`h_rad` もそろえる。

**R3. `w:numStyleLink`**: 番号付けスタイルを経由する定義をたどらないので番号が空になり、`structure.py:882` は `autonum` が空だと
`ListNode` にしない。生成文字なので不変性チェックは合格し、知らせも出ない。`w:styleLink`／`w:numStyleLink` をたどる。

**K3. キャプションの 2 段落目以降**: `linker.body_paragraphs` が `FigNode.caption`・`TableNode.caption` だけを返し `caption_more` を
返さない。`pdfmatch.target_paragraphs` も同じ関数で集める。出典行の引用・URL・注番号がリンクにならず「見つからない」にも出ず、
ルート1 の 13 章にも違いが出ず、ルート2 でも直さない。`caption_more` も文脈 "caption" で返す。

**K4. 枝番つきの図表番号**: `RE_FIGCAP`/`RE_TABCAP` と `RE_FIGREF` が整数だけを読むので、図1-1・図1-2 は両方「図1」、
本文の「図1-2」は「図1」＋並びの「2」と読まれ、「図1-1」「図1-2」のどちらの参照も後の図へ、「2」は図2.1 へリンクされる
（4 章に「図番号 1 が重複」の記録だけ）。枝番を番号の一部として読むか、重複した番号の参照はリンクしないで記録する。

**K5. 本文の「注」だけの段落**: `back_heading_by_text` が本文スタイルの「注」（表の注の見出しなど）に合うと後付けに切り替わり、
本文には戻らないので、以降の章見出し・本文がすべて 1 件の注の段落になる。その後ろに章見出しのスタイルが現れたら本文に戻すか、
要確認にする。

**A3. AI の MathML の実体参照・コメント・処理命令**: `parse_mathml` は `resolve_entities=False` で読み、`el.iter()` で要素でない
ノードを素通しする。`<!DOCTYPE math [<!ENTITY foo "abc">]>` 付きの MathML は `<mml:mi>&foo;</mml:mi>` のまま出力に入り、
`validate.py` も `resolve_entities=False` なので「妥当」と報告する。J-STAGE では XML として読めない。`parse_mathml` で
`isinstance(x.tag, str)` でないノードがあれば不採用にし、`final_check` で通常のパーサでも読めることを確かめる。

**A4. 見出し行だけの表**: `n_head == len(rows)` だと `<thead>` だけの `<table>` になり DTD（`thead?, tfoot?, tbody+`）に合わない。
Word で 1 行の表に「タイトル行の繰り返し」を付けた原稿で起きる。全行が見出しなら `thead` を作らない。

**A5. 謝辞の中の別行数式・表**: `backsec` が `<ack>` の直下に `<disp-formula>`・`<table-wrap>` を書くが、`ack` の内容モデルは
`(label?, title?, abstract*, kwd-group*, p*, sec*, ref-list*)`。`<notes>`・`<app>` は可。`<p>` で包む。

**A6. xref を出せない文脈へのリンク**: `apply_ops` は段落の文脈を見ず、`emit.link_element` は `ctx.xref` が偽なら黙って文字だけ書く。
題目の段落への `link_figure` が「採用」として 2 章に載るが XML にリンクはない。`plan.no_link_paras()` に当たる段落への
link_* を不採用にする。

**A7. 付記・謝辞・資料の自動番号**: `backsec`・`app_children` は PNode だけを扱い `span(skip_gen=True)` で gen アトムを捨てる。
Word で見える番号が XML にないが、生成文字なので不変性チェックにも 8 章にも出ない。本文と同じく `<label>` の gen を出す。

**A8. formula_image にした図の表・移した画像**: `fig()` は表・`extra_images` を書いた後に `<fig>` を外し、`formula_image()` は
`image_paras` の画像しか書き直さない。表は不変性チェックで止まるが、`extra_images` は `info.images` に残るので `lost_images` が
見逃す。`formula_image` の検証で `fig.tables or fig.extra_images or fig.caption_more` があれば不採用にする。

**O1. 1 画面版の想定外の例外**: `AppState._run` が `rmtree(out_dir)` してから `convert` を呼び、`AIRequiredError` 以外の例外では
`self.res` が前の結果のまま残る。Gradio は例外を「Error」とだけ出すので、画面は前の結果を表示し、「結果をダウンロード」で
`FileNotFoundError`。`_run` の最初で `self.res = None` にし、`on_convert`/`on_apply` で `Exception` を `error_box` に出す。

**O2. 知らせの本文の手順番号**: `images_action` の「手順 7「足りない画像をアップロード」で…」、`_textbox_undecided_action` の
「手順 4 で…手順 5 から」、`_upload_action`・`_pdf_*_action`・`lost_action` の「手順 2 で…」、`_ai_pending_action` の「手順 5 の依頼文…
手順 6 に貼り付けて ▶」が、1 画面版（README では一般の利用者用）でもそのまま出る。`Action` に画面に依存しない文を書き、手順の
部分は画面側（ノートブック／app）で添える仕組みにする。
