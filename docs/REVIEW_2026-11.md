## 詳細

### S1

**K1. 後付けの見出しが同じ種類で 2 つあると、先の見出しが出力も除外もされない**
`structure.build_back` が `plan.notes = BackSec(heading=b)` / `plan.ack` / `plan.fn_heading` / `plan.ref_heading` を無条件に上書きする。
「引用文献」と「参考文献」を別の節にした原稿では先の「引用文献」の見出しが、「付記」「謝辞」が 2 回あるときは先の節の段落がすべて、
XML にも除外の記録にも入らない。再現: `make_article()` の `refs` で「参考文献」の見出しと文献を足す →
`fidelity.missing=[('d13', '引用および参考文献')]`、要対応「変換ツールの不具合の可能性」。
直し方の案: 2 つ目以降は前の節に続ける（見出しの段落は前の節の段落として出し、判断の一覧に記録する）か、要確認で知らせる。

**K2. 所属だけの段落・行が続くと、前の所属と最後の所属が落ちる**
`author_paragraph_ja` の `self._loose_affs = [p]` が前の所属を捨て、著者が続かない最後の所属は誰にも付かない。著者表でも
`current_affs = row_affs` で前の行の所属を捨てる。所属が 2 つある著者を所属 2 行＋著者 1 行で書いた原稿で起きる。
再現: 著者表に「第二大学／（空）」の行を足す → `missing=[('d6', '第二大学')]`。直し方の案: 所属は著者が現れるまでためて全部付け、
著者のない所属は除外に記録して要確認にする。

**P1. 全角・半角の直しが止められても、隣の空白の削除だけが残る**
`drops`（全角・半角を直す文字のすぐ隣の半角空白）は、その `width` の Fix が後段で直さないことになっても `space` の Fix として直される。
経路は 3 つ: (a) 構造の確かめ（`_lost` → `_protect`）で `width` が `STRUCTURE_REASON` になる、(b) `width` の文字がほかの作成者の
`w:ins` やフィールドの結果の中で直せない、(c) 注の番号を守る `NOTE_REASON`。結果は「本文 (挿入の文字) の後ろ」→「本文(挿入の文字)の後ろ」で、
docx とも PDF とも違う。`verify_supplement` が `UNIT_WHY` で不合格にするので黙っては通らないが、利用者には原因の分からない要対応になる。
CLAUDE.md の「(A) の直しは typeset_pair の対と drops を超えて文字を変えない」に反する。直し方の案: `plan_fixes` で `space` の Fix を根拠の
`width`／番号の Fix と同じ `group` にする（group の一部が直せなければ全部直さない仕組みに乗る）。

**P2. 入力の docx が出力の「…_PDFで補完した原稿.docx」と同じパスだと入力を壊す**
`write_fixed_docx` が `src_path` を読みながら同じ `dst_path` を `ZipFile(dst, "w")` で開くため、入力が 22 バイトに切り詰められてから
`BadZipFile` で止まる。利用者が補った docx を却下して保存し、同じ出力フォルダでルート2 をかけ直すと起きる。
直し方の案: `pipeline.convert` で `docx_path.resolve() == fixed.resolve()` なら別名にするか中止する。

**A1. AI の回答の項目の型が違うと TypeError で変換が止まる**
`split_ops` は `occurrence` 以外の型を確かめないので、`src`・`target`・`role`・`image`・`after`・`caption`/`body` の要素が一覧や辞書だと
`unhashable type`、`text` が数値（`"text": 2001` は現実的）だと `normalize()` の TypeError になり、`pipeline.convert` は捕まえない。
手動モード（チャットの貼り付け）と Sakana AI のスキーマなしの再試行で起こりうる。レポートも XML も出ない。
直し方の案: `split_ops` で 12 項目を文字列に正規化し、placements も `_placement_problem` の先頭で型を確かめて不採用にする。

**A2. `notes` が一覧でないと例外**
`pipeline.py:373` の `[str(n) for n in data.get("notes", [])]`。整数なら `'int' object is not iterable` で中止、文字列なら
`['気', 'づ', 'き']` のように 1 文字ずつの気づきになる。`parse_response` で型を確かめる。
