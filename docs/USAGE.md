# 使い方（利用者向け）

このツールは、『全国数学教育学会誌 数学教育学研究』の論文（Word の .docx）を J-STAGE の全文 XML に変換します。ここでは Google Colab のノートブックでの使い方、結果の見方、できないことを説明します。概要は [README.md](../README.md)、AI の API キーの作り方と手動モードの詳しい手順は [USAGE_AI.md](USAGE_AI.md) にあります。

## 一般の利用者用（1 画面）の使い方

[![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/thjpme/jstgxmlcng_JASME/blob/main/notebooks/JASME_docx_to_JSTAGE_XML_GUI.ipynb)

1. 上のボタンからノートブックを開き（Google アカウントが必要）、セルの ▶ を押します。ツールの準備（2 分ほど）のあと、その下に画面が開きます。
   メニューの「表示」でサイドバーなどを閉じると広く使えます。このノートブックのタブは閉じないでください（閉じるとランタイムが止まり、画面も消えます）。
2. 画面で、作り方（下の「出版版 PDF との照合と、2 通りの作り方」）を選び、docx と PDF を選びます。巻・号・最初と最後のページ・査読の有無・
   原稿種別を入れると「変換する」が押せるようになります（足りない項目は画面に出ます）。キーワード・日付・責任著者・DOI は「任意の項目」を開いて入れます。
3. AI による仕上げの方法（下の「AI による仕上げの選び方」。1 画面版の API は Claude だけで、ChatGPT・Gemini・Sakana AI〈動作を確かめていません〉は従来版で選びます）を選び、「変換する」を押します。API を使うときは、Colab のシークレットに
   API キーを登録しておきます（[USAGE_AI.md](USAGE_AI.md)）。
4. 結果は同じ画面の下に出ます（要対応は赤、要確認は黄の枠、結果の要約、畳んだレポート全文。下の「変換レポートの見方」）。
   手動モードでは依頼文が出るので、チャットに貼り付け、返ってきた回答を貼って「反映」を押します。画像の要る図・表があれば、
   結果の下に「図の画像（あと N 枚／全部で M 枚）」の欄が出ます。出版版 PDF から切り取った画像を「まとめて入れる」に選ぶと、
   ファイル名（fig04.png・図4.png・29_55_fig04.png など）で図に合わせます。名前で合わなかったファイルは知らせるので、図ごとの行（ラベルは
   「図のキャプション（画像の名前）— 未／入れた: ファイル名／入れない」）で選び直し、「画像を入れる」を押します。一部の図だけ入れてもかまいません。
   キャプションのない画像の行には「入れない」のチェックがあります（チェックを外して「画像を入れる」を押すと、「入れない」をやめて未に戻ります）。
   行で選んだ画像と「まとめて入れる」の画像が同じ図に合ったときは、行の画像を入れ、まとめての方は入れなかったと知らせます。入れた後は、欄の下の「図の確かめ」（画像と図番号・キャプションの一覧）で
   取り違えがないかを確かめます。行は 30 個までで、超える分は「まとめて入れる」で入れます（下の「できないこと・注意点」）。
   変換の後に入力（docx・PDF・作り方・ページ・日付など）を変えたら、「変換する」を押し直してください。押し直すまでは、「反映」「画像を入れる」
   「結果をダウンロード」は、変わった項目を示して断られます（今の結果は変える前の入力で作ったものなので、別の論文と混ざらないようにするためです）。
   入力を前回の変換のときの値に戻せば、そのまま続けられます（同じファイルを選び直したときは、変わっていない扱いになります）。
   「AI による仕上げの方法」と MODEL の変更は、次に変換するときから使われます。別の論文の docx に変えて変換すると、AI の回答の欄は空になります
   （前に別の依頼文に対して反映した回答をそのまま貼っても断られます。依頼文そのものや、依頼文にある「回答の見本」をそのまま貼ったときも断られます。貼るのは、チャットの AI が返したコードブロックです）。
5. 「結果をダウンロード」を押し、出てきた「ZIP を保存」を押すと、ブラウザのダウンロードフォルダに `変換結果_巻_開始ページ.zip` が保存されます（J-STAGE にアップロードする ZIP・XML・変換レポートのほか、`巻_開始ページ_図の確かめ.html` も入っています。展開すると入れた画像も見えます）。
   要対応が残っているときは一度止まるので、直して変換し直すか、「このままダウンロード」にチェックを入れてもう一度押します
   （変換の後に入力を変えたときは、「このままダウンロード」にチェックを入れても断られます。上の 4.）。
6. 続けて他の論文を変換するときは「次の論文」を押します（ファイル・ページ・キーワード・日付・DOI が空になり、巻・号・査読の有無・原稿種別・AI の設定は残ります）。
7. J-STAGE の編集登載システムで、その号の巻・号と**セクション**を作成し、ZIP の中の `jasme_巻_開始ページ.zip` をアップロードします（下の従来版の 3.・4. と同じ）。

## 従来版（手順ごとのセル）の使い方

[![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/thjpme/jstgxmlcng_JASME/blob/main/notebooks/JASME_docx_to_JSTAGE_XML.ipynb)

入力欄の値を残したまま続けて変換するときや、1 画面版がうまく開かないときに使います。

1. 上のボタンからノートブックを開きます（Google アカウントが必要）。
2. 上から順に、各セルの ▶ を押します。**前の手順の実行が終わってから、次の手順の ▶ を押してください**
   （前の手順を飛ばすと「先に手順 ○ を実行してください」と表示されて止まります）。
   1. 準備（最初に 1 回。1 分ほど）。「準備ができました」とツールの版が表示されたら、手順 2 に進みます
   2. 作り方（「docx から作り、出版版 PDF で補う」（初期値）/「docx から作る」）を選び、論文の docx と PDF をアップロード（docx 用・PDF 用の
      ボタンが順に出ます）。PDF がまだないときは「docx から作る」を選びます（下の「出版版 PDF との照合と、2 通りの作り方」）
   3. 巻・号・ページ・査読の有無（必須）・キーワード（任意。日本語・英語を別の欄に「;」区切り）・日付・原稿種別（選択）を入力。
      巻・号・ページは半角の英数字で入力します（全角の数字は半角にして読み、その旨を表示します。「31巻」のように英数字以外が
      あると止まります）。日付は 2026-03-31 の形で（2026/3/31・2026年3月31日 でもかまいません）
   4. AI による仕上げの方法を選ぶ（使わない / API で自動実行（Claude / ChatGPT / Gemini / Sakana AI。Claude 以外は動作を確かめていません） / 手動。初期値は手動）
   5. 変換を実行 → 画面に変換レポートが表示されます
   6. （手動モードのときだけ）AI の回答を貼り付けて再変換
   7. （画像の要る図・表があるときは毎回）図の画像を入れる。まだ画像を入れていない図ごとに「ファイル選択」ボタンが出るので、出版版 PDF から
      図の部分だけを切り取った画像（PNG か JPEG。キャプションの行は写さない。ファイル名を fig04.png・図4.png のようにしておくと、名前で図に合わせます）を
      「まとめてアップロード」で選びます。名前で合わなかった画像は、図ごとに選び直せます。キャプションのない画像を入れないときは、`NO_IMAGE` に
      名前（img3fa9c2 など。コンマ区切り）を書いてから ▶ を押します（名前が違っていれば、アップロードを求める前に断ります）。入れた後は、図の確かめの一覧が表示されます（下の「できないこと・注意点」）。
      全部入れた後に画像を差し替えるときは、`REPLACE` にチェックを入れてから ▶ を押し、差し替える画像を fig04.png のような名前で選びます（差し替えたらチェックを外します）
   8. 結果（`変換結果_巻_開始ページ.zip`。J-STAGE にアップロードする ZIP、XML、変換レポートのほか、図の確かめ.html も入っています。展開すると入れた画像も見えます）をダウンロード。「docx から作り、出版版 PDF で補う」では、（PDF の文字を読めたとき）PDF で補った
      docx も入っています。要対応（赤い枠）が残っていると、ダウンロードの前に一度止まります（直さずにダウンロードするときは、
      もう一度 ▶ を押します。下の「変換レポートの見方」）
   9. （続けて他の論文を変換するときだけ）▶ を押してから手順 2 に戻る（下の「複数の論文を続けて変換するとき」）
3. J-STAGE の編集登載システムで、その号の巻・号と**セクション**（目次の見出し。例: 論文）を作成しておきます
   （ないとアップロード時に「学会誌別セクションが存在しません」というエラーになります）。
4. ダウンロードした中の `jasme_巻_開始ページ.zip`（例: `jasme_31_1.zip`）を編集登載システムにアップロードし、記事をセクションに振り分けて、
   プレビューで確認します。
   **J-STAGE では PDF が必須です。** 手順 2 で PDF をアップロードすると ZIP に入ります。

## 複数の論文を続けて変換するとき

1 本ずつ変換します。同じ画面のまま、次のように繰り返します（手順 1 の準備はやり直さなくてかまいません）。

1. 1 本目を手順 8 まで済ませ、結果をダウンロードします。ダウンロードされるファイルの名前は論文ごとに違います
   （`変換結果_巻_開始ページ.zip`。例: `変換結果_31_1.zip`）。
2. **手順 9「続けて他の論文を変換する」の ▶ を押します。** 前の論文のファイルと入力の記録が片付き、手順 2 から始められる状態になります。
   結果をダウンロードしていないときは、一度止まって確認を求めます（もう一度 ▶ を押すと、ダウンロードせずに進みます）。
3. 手順 2 で次の論文の docx と PDF をアップロードします。
4. 手順 3 の入力欄には、**前の論文の値が残っています。** ページ・査読の有無・最終査読日・キーワード・受付日・受理日・責任著者などを、
   今回の論文のものに書き換えてから ▶ を押します（号・発行日・公開日など、同じ号で共通の値はそのままでかまいません）。
   巻と最初のページが前の論文と同じままだと止まり、キーワードや日付が前の論文と同じ値のときは注意が表示されます。
5. 手順 4（方法を変えないなら、そのまま ▶）、手順 5、（手動モードなら）手順 6、（画像の要る図・表があれば）手順 7、手順 8 を実行します。
   手動モードでは、手順 6 の欄に前の論文の AI の回答が残っています。今回の論文の依頼文を AI に渡し、返ってきた回答に貼り替えてください
   （前の論文の回答のままだと、回答を 1 件も反映せず、「AI による仕上げ」の「失敗」で知らせます）。
6. J-STAGE には、論文ごとの `jasme_巻_開始ページ.zip` を 1 つずつアップロードします。

入力欄の書き換え漏れが心配なときは、手順 9 を使わずに、ノートブックを開き直して（上の「Open in Colab」のボタンから）手順 1 からやり直すほうが確実です。
GitHub のノートブックを開き直すと、入力欄は初期の値に戻ります。

しばらく操作しないでいると、Colab の接続が切れて（ランタイムが終了して）、アップロードしたファイルや入力の記録が消えます。
そのときは手順 1 からやり直してください。

> ツールが新しくなったときは、メニューの「ランタイム」→「セッションを再起動」を選んでから手順 1 からやり直してください
> （同じランタイムで前の版を使った後に手順 1 を実行すると、その旨が表示されて止まります）。
> 開発中の版を試すときは、手順 1 の「USE_DEV_VERSION」にチェックを入れて実行し、表示される欄にブランチ名を入力します。

## AI による仕上げの選び方

AI による仕上げ（図・表の位置合わせ、リンクの取りこぼしの確かめなど）は**強く推奨**します（必須ではなく、使わなくても XML・ZIP はできます）。
どの方法でも、**AI に出版版 PDF を渡すことを強く推奨**します。PDF があると、AI が PDF のページを見て、図・表を出版版と同じ位置に置けます。
手動と API（Claude）のどちらでも同じ仕上げができます。違いは、依頼文を自分でチャットに渡すか、ツールが API で送るかだけです。

| 方法 | 必要なもの | 送るもの・送信先 | 向いている場面 |
|---|---|---|---|
| 使わない | なし | どこにも送らない | AI を使えないとき（テキストボックスなどに入った図表で、位置を機械的に決められないものは、結び付いた段落の後ろに置く） |
| 手動（初期値） | claude.ai などのチャット（API キー不要） | 本文（依頼文）と出版版 PDF を、利用者が貼り付け・添付したチャットに | はじめて使うとき、論文が少ないとき、AI に渡す内容を自分で確認したいとき |
| API で自動実行（Claude） | Claude API キー（Colab の「シークレット」に `ANTHROPIC_API_KEY` として登録。作り方は [USAGE_AI.md](USAGE_AI.md)。利用料がかかります） | 本文（依頼文）と出版版 PDF を、Anthropic（Claude API）に | 毎号まとめて、何本も続けて処理するとき（貼り付けの手間がない） |
| API で自動実行（ChatGPT / Gemini / Sakana AI） | 各社の API キー（シークレットに `OPENAI_API_KEY` / `GEMINI_API_KEY` / `SAKANA_API_KEY` として登録）と、使うモデルの名前 | 本文（依頼文）と出版版 PDF を、OpenAI / Google / Sakana AI に | Claude の API を使えないとき（動作を確かめていません） |

**言い方について:** 画面の欄「AI による仕上げの方法」で方法を選び、残っていることは推奨の手順「AI による仕上げ」（青い枠。見出しは
「AI で図・表の位置を合わせる（残り 3 個）」「AI に出版版 PDF を見せて、図・表の位置を合わせ直す」など、残っていることに合わせて変わります）
で知らせます。レポートでは 2 章「AI による仕上げ」です。「補完」は、出版版 PDF で docx を補う作り方（下の「出版版 PDF との照合と、2 通りの作り方」）
の意味でだけ使います。

**AI の回答で XML を直すのは、図・表の位置、文字だけのテキストボックスの種類と位置、リンク、姓名の境目、注の区切り・資料の始まりだけです。**
見出しの階層・引用・謝辞・付記・英文要旨・除外などの段落の役割（スタイル）は、AI の回答では XML を直しません（0.33.0 から。前の版は AI の
指定で謝辞・引用・見出しの階層を直していました）。AI の提案は要確認「スタイルを確かめてください」（`style_check`）の行に載せるので、
**Word で直して変換し直してください**: Word でその段落を選び、［ホーム］のスタイルの一覧から、行の提案のスタイル（謝辞の見出しなら
「謝辞見出し」、引用なら「ブロック引用」、節・項の見出しなら「節見出し」「項見出し」など）を選んで保存し、変換し直します
（API モードでは AI を呼び直すので、料金がかかります）。直さなければ、AI の回答を使っても、その段落は AI なしの変換と同じ形
（たとえば謝辞が通常の段落、引用が本文の段落、見出しが箇条書き）で出ます。謝辞の見出しが本文の段落のままだと、謝辞の段落が
本文に残るので、AI が図・表をその段落の後ろに置くこともあります（直せば本文の最後の図・表の位置に戻ります）。

**2 段にまたがる図・表**: Word で段落の位置に置かれた（本文の流れの中の）図形でも、2 段組みの 2 段にまたがる大きな図・表は、Word の位置と
出版版の位置がずれやすいので、AI が出版版 PDF を見て答えたときだけ、AI の答えた位置に置きます。PDF を見ていない回答（PDF を渡して
いない・AI が見ていないと答えた・ページ数が合わない）では、AI の答えを使わず、Word の位置のままにします（レポート 2 章の
「採用しなかった提案」に理由が出ます）。

「API で自動実行」は ChatGPT（OpenAI）、Gemini（Google）、Sakana AI（Sakana Namazu・Sakana Fugu）の API にも対応していますが、**推奨は Claude です**
（AI への依頼文と動作の確認は Claude で行っています）。Claude 以外の API キーの作り方・料金・利用規約（送信した内容の扱い）は、
各社の案内を自分で調べて確かめてください。使うモデルの名前は手順 4 で自分で入力します。**Claude Opus と同等以上の性能のモデル
（各社の最上位クラスのモデル）を推奨します。** 性能の低いモデルでは、取りこぼしや誤った提案が増えます
（誤った提案はプログラムの検証で採用されませんが、仕上げの効果が下がります）。
**Sakana AI は、既定で送信した内容をモデルの学習に使う設定です。** 未公開の原稿を送るので、使う前に Sakana AI の管理画面（Console）の
設定で、学習への利用を止めて（オプトアウトして）ください。

手動モードでは、ツールが「AI依頼文.txt」を作ります。ノートブックの手順 5 の結果の先頭（とレポートの後ろ）に、依頼文が「依頼文をコピー」ボタン付きの
枠で表示されるので、チャットに貼り付け（依頼文の最初の【作業する方へ】のとおり、この論文の出版版 PDF を同じメッセージに添付して
送るのを強く勧めます。ツールに PDF を渡していれば、そのファイル名が書かれます）、
返ってきた回答をノートブックの手順 6 に貼り戻すと、API モードと同じ検証・反映・最終チェックが行われます。
1 画面版では、依頼文の欄（「依頼文（新しいチャットに貼り付けて送る）」）が結果の上に出るので、同じようにチャットに渡し、
返ってきた回答を「AI の回答（json のコードブロック）を貼り付ける」欄に貼って「反映」を押します（「変換する」は回答なしで作り直すので、回答を反映するときは押しません）。
コマンドラインでは、回答をファイルに保存し、`--ai manual --ai-response 回答のファイル` を付けて実行し直します（`--ai` の既定は manual で、指定がなければ依頼文 `AI依頼文.txt` を書き出すだけです。依頼文は、出版版 PDF と一緒にチャットに渡してください）。
`--ai none`・`--ai api` で `--ai-response` を指定すると、引数の誤りとして終了コード 2 で止まります。
回答は `json` のコードブロック 1 つで返すよう依頼文で指示しているので、**コードブロック右上のコピーボタン**でコピーしてください。
コードブロックになっていない回答や、文字列が飾りの引用符（“ ”）で囲まれた回答は読み込まず、どこが読めないかを表示します
（推測で直すと AI の指示を取り違えるおそれがあるため）。その場合はチャットで出し直しを頼んでください。
回答が長すぎて途中で切れていたときは、最後まで書かれていた図表の位置の指定だけを反映し（リンクなどは反映しません）、

最初から最後まで貼り付け直してください（続きだけを貼り付けても読めません）。

## 変換レポートの見方

冒頭の「結果の要約」で、次の 3 つがすべて「合格」であることを確認してください。

1. **本文の文字の不変性チェック** — docx の全段落の文字が XML に過不足なく出力されたか（AI による仕上げの後に実施）
2. **最終出力の再チェック** — 作業用の目印を取り除いた最終的な XML でも文字が一致するか
3. **J-STAGE 指定 DTD による検証** — XML が J-STAGE の DTD（JATS 1.1）に適合するか

要約の「出版版 PDF との照合」に「要確認」があれば、13 章で PDF と違う箇所（「docx から作り、出版版 PDF で補う」では、補った校正の直しと直さなかった箇所）を確認してください。
組版の違い（全角・半角・ダッシュ・引用符など）は 13.2 に載りますが、確認は要りません。ルート2 では、補った docx が元の docx から
組版の違いと報告した直し以外に変わっていないかを変換の最後に確かめ（補完の確かめ。レポートの 1 章と 13.8）、不合格なら要対応になります。
PDF を照合したときは、13 章の最後の「照合に使わなかった PDF の文字」も見てください（要約に「照合に使わなかった PDF の文字 ○ 件」、
14 章に確かめる項目が出ます）。段落の途中にあった PDF の文字のうち、組版で入る文字（誌名の行・柱・投稿受付日など）や、docx にない
図・表の中の文字（表のセルの数字、図の中の語句など）とみなして、照合に使わなかったものの一覧です（段落ごとに 1 行。表のセルの数字は
件数と最初のいくつかにまとめます。行の変わり目は「⏎」）。これらの文字は、PDF で補った docx にも入れません。表・図の中の文字や、
docx のほかの段落にすでにある文字なら、対応は要りません（「docx から作り、出版版 PDF で補う」では、その文字を 13 章の「PDF で補った校正の直し」
で元の段落から消していないかも確かめてください）。PDF では本文なのに docx にない文字（校正で足された一文など）があったときだけ、
docx を手で直してから変換し直してください。

要約の下に「要対応」「要確認」の囲みがあれば、それぞれの対処に従ってください（14 章のチェックリストにも載ります）。

  箇条書きの記号は Word の箇条書きの設定が付ける記号で、打ち直せないので、Word でその箇条書きを選び、［ホーム］の箇条書きの▼にある
  ［新しい行頭文字の定義］で、普通の記号に選び直します。本文の文字は、Word でその記号を普通の文字（［挿入］の［記号と特殊文字］から Unicode の記号）に
  打ち直します。どちらも、直したら変換し直してください。
- **要確認「Word では表示されるのに、XML に出せていないかもしれない文字（囲い文字など）があります」（`resultless_field`）** — Word の「囲い文字」機能や
  EQ フィールド（分数・根号・ルビ・組み文字）、記号のフィールド、フォームのチェックボックスなど、Word が「フィールド」というしくみで描いて表示している文字は、
  docx に文字として入っていないので、XML には出ません（元の原稿が特殊な作り方をしているときです。囲い文字を合成して文字にすることはしません。
  出版版 PDF で補った変換では、PDF から別の文字として補われていることがあります）。知らせには、段落ごとに 1 行で、段落の文字の抜粋と種類を載せます
  （文字のある位置に［ここ］の印。レポートの表示だけで、XML には入りません）。行は先頭の数件だけで、ほかは「ほか N 段落」とし、全件は 6 章に載せます。

  本文の記号か）・フォント・置き換えた文字ごとに件数でまとめて知らせ、本文の記号は段落の場所と前後の文字を添えます（全件は 8 章）。

  Word の［新しい行頭文字の定義］で選び直し、本文の記号は Word で普通の文字に打ち直して、変換し直します。よく使う記号（Wingdings の●・➢・▪・✓・❖の
  箇条書きの記号と、Symbol フォントの矢印・ギリシャ文字などの記号）は、以前の版から同じ文字にしているので、この知らせは出さず、8 章の表にだけ載せます。
- **手順「図の画像を入れてください」（`images`。必須）** — 図・表の画像は、作業する人が出版版 PDF から用意して入れます（docx の中の画像は使いません。
  Word のトリミングや加工、Word の図形で描いた図も、PDF の見た目のまま切り取れば済みます）。枠に、画像の要る図・表（名前 fig04・tab01・img3fa9c2 など）の
  残りが出ます。全部入れるまでは、ダウンロードの前に一度止まり、コマンドラインの終了コードは 1 です。docx で 1 つの図に画像が 2 枚以上あるときも、
  図 1 つに画像 1 枚（PDF から図全体を切り取ったもの）を入れます（9 章の備考「1 枚にまとめた画像を入れてください」）。
  キャプションのない画像（img…）は、出版版 PDF で見て、ほかの図に写っている・飾りだけ、のときは「入れない」ことにできます（コマンドラインは
  `--no-image img…`。複数あるときはコンマ区切り）。入れない画像は XML から取り除かれ、「全部で」の数から除かれます。図・表の画像は入れないことにできません。
  変換し直したとき（Word で直した原稿、AI の回答の反映）は、前に入れた画像を、同じ図（番号とキャプションの文字が同じ。キャプションのない画像は前の文章も同じ）だけに
  自動で入れ直します。図が増えて・消えて番号がずれたとき、同じキャプションの図が 2 つ以上あってどれがどれか決められないとき、キャプションが番号だけのときなど、
  別の図の画像を入れないために入れなかった画像は、この手順の枠と 9 章に「入れ直してください」と出ます（「今の fig02 の画像と思われます」の行は、
  その図にその画像そのものを入れると消えます）。別の論文に替えて変換したときは、前の論文の画像は入れず、画像が残っているうちだけ 1 行で知らせます。

  切り取って入れます。枠・白い四角・線・矢印・文字の図形だけの集まりの図形（飾り）は、画像の場所に数えず、9 章に記録するだけです（知らせません）。
- **要確認「キャプションが変わった図に、前の画像を入れ直しました」（`image_changed`）** — 変換し直したとき、キャプションが少し変わった図に、
  前に入れた画像を入れ直しました。図と画像が合っているか、「巻_開始ページ_図の確かめ.html」で確かめてください。違っていれば、正しい画像を
  入れ直してください（その図に画像を入れ直すと、この知らせは消えます）。
- **要確認「同じ画像が 2 つ以上の図に入っています」（`image_same`）** — 入れた画像のうち、中身がまったく同じものが 2 つ以上の図に入っています。
  同じ画像を 2 つの図に取り違えて入れていないか、「巻_開始ページ_図の確かめ.html」で確かめてください（本当に同じ画像の図なら、そのままでかまいません）。
- **要対応「XML の画像の名前に不具合があります」（`image_names`）** — XML の中の画像の名前が、画像を入れる場所の一覧と合いません。変換ツールの
  不具合の可能性があるので、この XML は登載に使わず、変換レポートを添えて開発者に知らせてください（ふつうは出ません）。
- **要対応「英文要旨が見つかりません」（`abstract_missing`）** — 英文の部分に「英文要旨」（または「英文要約」）のスタイルの段落が 1 つもなく、
  英文の題目・著者名・所属以外の段落の位置を決められないため、XML に出力していません（6 章に全文。理由の列に「（要対応）」）。英文要旨は XML に
  必要な内容です。Word で要旨の段落に「英文要旨」スタイルを（見出しの Abstract には「英文要旨見出し」スタイルを）付けて、変換し直してください。
  英文要旨がないために資料（「資料1」などの見出しと表）も出力できていないときは、そのことも書きます（英文要旨を直すと資料も出力されます）。
  AI による仕上げを使うと、AI の見立て（どの段落が英文要旨か）を 1 行添えます。XML には反映しないので、Word でスタイルを付けて変換し直してください。
- **要確認「論文の中の位置を決められない段落 ○ 件を、XML に出力していません」（`excluded_unsure`）** — 冒頭部（題目〜最初の章見出し）の題目・著者以外の
  段落・表、著者表の中の所属・著者名以外の文字、後付けの位置が分からない表（注のない注の節の表など）、本文と後付けの間の段落、英文の部分の
  題目・著者・要旨・資料以外の段落・表など、スタイルや位置から論文のどこに入るかを決められなかった段落です（6 章に全文。理由の列に「（要確認）」）。
  知らせに、種類ごとの件数と Word での直し方（付けるスタイル・移す位置）を載せます。本文などに必要な文字なら、Word で直して変換し直してください
  （XML に入れない文字なら、そのままでかまいません）。テンプレートの装飾行（記号だけの行）と誌名行（「全国数学教育学会誌　数学教育学研究」）は、
  知らせずに出力しません。
- **要対応「画像を入れる場所を作れなかった画像」（`lost`）** — 引用文献・注の節や、題目・著者名・所属の段落、XML に出力しなかった段落（冒頭の装飾など）の
  中にあるため、XML に画像を入れる場所を作れなかった画像です（このままでは J-STAGE に載りません。9 章に、画像ごとの段落と理由の推定）。Colab では
  赤い枠、コマンドラインでは表示と終了コード 1 でも知らせます。資料の図なら、Word で資料（見出しと中身）を英文要旨の後ろ（論文の最後）に移して、
  変換し直してください。題目・著者名・所属の段落の中の画像は本文の段落に移し、要らない画像なら Word で消します（下の「できないこと・注意点」）。
- **要確認「囲みか図の注記か決められないテキストボックス」** — 文字だけのテキストボックスのうち、問題文などの囲みか、図に重ねた注記か、文字数・幅・
  画像との近さから決められなかったものです。文字は XML に出力していません（6 章に全文、3 章にどのテキストボックスかを載せます）。本文に必要なら、
  AI による仕上げで囲みに指定するか、Word でテキストボックスの外に出してから変換し直してください（AI の回答を反映した後も決められなかったときは、
  手動モードならチャットで AI に出し直してもらって回答を貼り直し、API モードならもう一度変換します。1 画面版は、この知らせが出ているあいだ手動の欄が
  見えたままです）。
- **要確認「位置を推定した囲み」** — 文字だけのテキストボックス（問題文などの囲み）を `<boxed-text>` として XML に出力しましたが、Word での
  表示位置を docx から決められないため、結び付いた段落のすぐ後ろ（結び付いた段落が引用文献などの本文の外にあるときは本文の最後）に置いたものです。
  PDF と見比べ、位置が違うときだけ、XML の中で `<boxed-text>` を正しい位置に移してください（XML の囲みには ID がないので、レポートの 3 章に
  示す囲みの最初の文字と置いた位置で探します）。AI による仕上げを使えば、AI に位置を指定させることもできます。
- **要確認「図の画像に写るものとして、XML の本文に出していない文字があります」（`textbox_figure_text`）** — 図・表の入った図形（テキストボックス・
  グループ図形）の中の、キャプションでない文字（図の説明・出典など）は、図の画像に写るものとして XML の本文には出していません（6 章に全文）。
  知らせには、図形ごとに 1 行で、どの図の図形か（図4（fig04）、キャプションのない画像 img… と場所、本文の図キャプションに含めた図形など）と字数を出します。
  入れる画像にその文字が写っているか確かめ、本文として読ませたい文字なら、Word でその文字を図形の外（本文の段落）に出して、変換し直してください。
- **要確認「英文要旨に、和文と思われる段落があります」** — 資料（付録）の和文が、英文要旨に入っているかもしれません（10 章）。
  資料なら、Word で資料の見出しの段落に章・節・項見出しのスタイルを付けて（見出しがなければ、資料の前に「資料1」「資料（授業プリント）」
  などの見出しを付けて）、変換し直してください。「資料1　授業プリント。」のように「。」で終わる見出しは文とみなすので、
  見出しのスタイルを付けると、文字はそのままで資料になります。
- **要確認「引用文献などの後ろに、資料の見出しと思われる段落があります」** — 今の版では、引用文献・注・付記・謝辞の後ろに置いた資料を
  資料として扱わず、その節の段落のまま出力します（10 章）。資料なら、Word で資料（見出しと中身）を英文要旨の後ろ（論文の最後）に移して、変換し直してください。
- **要確認「スタイルを確かめてください」（`style_check`）** — 見出し・引用などのスタイルが違うかもしれない段落を、1 か所 1 行で挙げます
  （先頭 10 行。残りはレポートの 2 章の「スタイルの提案」の表）。AI による仕上げを使ったときは、AI の Word での直し方の提案も添えます
  （AI の提案だけのときの見出しは「AI がスタイルの誤りを見つけました」）。AI の提案は XML には反映していません（AI の回答を入れても、
  その段落は今の形のまま出ます。上の「AI による仕上げの選び方」）。違っていれば、Word でその段落を選び、［ホーム］のスタイルの一覧から
  提案のスタイル（「謝辞見出し」「ブロック引用」「節見出し」など）を選んで保存し、変換し直してください。引用文献の節の「.」だけの段落のような、記号だけの段落（テンプレートの残りなど）も
  ここに挙げます。文字は変えずに引用文献の 1 件として出しているので、文献でなければ Word でその段落を消して変換し直してください。
- **要確認「AI の回答で、注の区切り（資料の始まり）を直しました」（`ai_boundary`）** — AI による仕上げで XML を直したのは、注の区切りと
  資料の始まりだけです（注の見出しの段落への指定、英文要旨の最初の段落を資料の見出しにする指定、変換ツールの判断と同じ指定、
  同じ段落への 2 つ以上の指定は使いません。2 章の不採用の一覧に理由）。直した段落を 1 行ずつ挙げます（2 章にも表）。出版版 PDF と見比べ、違っていれば、注は Word で注の番号を
  「2)」の形に直して AI の回答を入れずに、資料は Word で資料を英文要旨の後ろのセクションに分けて、変換し直してください。
  最初の資料の見出しを「資料の本文」にしたときは、前に続ける資料がないので、見出しのない資料になったことを行に書きます。
- **要確認「原稿を直す前の AI の回答を使いました」（`ai_carried`）** — Word で原稿（段落の文字やスタイル）を直した後の変換に、直す前の
  依頼文への回答を入れたときに出ます（図・表・文献・注の数と並びが同じときだけ使います）。段落の先頭の文字（head）で確かめられた指定だけを
  使い、確かめられなかった指定は使っていません（2 章の不採用の一覧）。すべての指定を使うには、今の依頼文で AI に依頼し直してください。
- **要確認「手で書いた注と Word の脚注・文末脚注が両方あり、注の番号が重なっています」** — Word の注にも 1 から番号を付けるので、
  注の一覧に同じ番号（「1)」など）の別の注が並びます（10 章）。Word で、どちらかの書き方にそろえてから変換し直してください。
- **要確認「スタイルの設定で隠し文字になっている文字を出力していません」** — 段落スタイル・文字スタイル・既定の書式の「隠し文字」の
  設定で、Word では表示されないと判断した文字・画像です（6 章に全文）。この判断は暫定なので、Word で（［ホーム］の［編集記号の
  表示/非表示］をオフにして）表示されないことを確かめてください。表示されるものがあれば XML から抜けているので、変換レポートを添えて
  開発者に知らせてください。文字に直接付けた隠し文字は、これまでどおり 6 章に載せるだけです。
- **要確認「題目・著者・所属・引用文献の中に改行があります」** — 改行（Shift+Enter）は、XML では改行の文字のまま出力しています
  （10 章。J-STAGE では、改行の位置が空白になるか、前後の文字が詰まって表示されることがあります）。要らない改行なら、Word で消して
  （英文なら空白に置き換えて）変換し直してください。

**変換を中止するとき**（XML・ZIP・レポートは作りません。コマンドラインの終了コードは 2）:

- **「原稿の構造を直す必要があります」** — 同じ種類の見出し（引用文献・注・付記・謝辞・英文要旨）が 2 つある原稿と、著者名の付かない所属の段落・
  著者表の行がある原稿は、そのまま変換すると、どちらかの段落の文字が XML に入らなくなります。docx の文字を 1 文字も変えずに XML にするため、
  どちらを残すか・どこにまとめるかをツールは決めず、変換を中止して、箇所ごとに段落の ID・文字の抜粋・Word での直し方を表示します（ノートブックは
  手順 5 の赤い枠、1 画面版は変換の結果の欄の赤い枠、コマンドラインは標準エラー）。Word で表示のとおりに直して保存し、docx を選び直して
  変換し直してください。直し方の概要:
  - 同じ種類の見出しが 2 つ: 後ろの見出しの段落を消して 1 つの節にまとめます。間に別の後付けの節（注など）があるときは、先に後ろの節の段落を
    前の節の最後に移してから、後ろの見出しを消します（見出しを消すだけでは、後ろの段落が間の節に入ってしまいます）。表の注の見出しなどの「注」
    だけの段落は、注の節の「注」1 つだけを「注見出し」スタイルにし、ほかは「注本文」スタイルにします。見出しでない段落なら、スタイルを本文
    （「参考文献」「英文要旨」など）にします。
  - 著者名の付かない所属: 所属の段落は、その後ろの著者名に付けて出力します。ほかの著者の所属なら、その著者名の段落のすぐ前に移します。1 人の
    著者に所属が 2 つ以上あるときは、テンプレートの著者表を使い、その著者の行の所属の欄に段落を分けて並べます。要らない所属なら消します。
  - 空白だけの見出しの段落は、中止せずに空白の段落として出力しません。
  - 出版版 PDF で補う作り方でも、補う前の docx で確かめます（補った docx は作りません）。AI による仕上げの回答の区切りの指定でこの形になるときは、
    中止せずにその指定を使わず、レポートの 2 章に載せます。

不変性チェックが不合格で、5 章に「変換ツールの不具合」とある（出力した段落が「出力しなかった段落」にも記録されている、など）ときは、
docx ではなくツールの誤りです。変換レポートを添えて開発者に知らせてください。

その後に、AI による仕上げ（方法・モデル・状態・利用量の表から始まる）、機械処理で解決できなかった箇所、機械的な推定、XML に出力しなかった文字（全件）、
構造化のために落とした空白（全件）、画像、書誌情報、出版版 PDF との照合（13 章）、登載前のチェックリスト（14 章）が続きます。

## 出版版 PDF との照合と、2 通りの作り方

受け取った docx が、著者校正を経た最終版とは限りません（組版で印刷所がかっこ・句読点を全角にそろえる、校正の直しが docx に戻されていない、など）。
記事の PDF をアップロードすると（ノートブックは手順 2、1 画面版は「PDF」の欄）、docx の文字と PDF の文字を段落ごとに照合します。XML はどちらの作り方でも docx から作ります
（PDF から XML を作るのではありません。構造は docx のスタイルから決めます）。作り方は、ノートブックは手順 2 の最初、1 画面版は「作り方」の欄で選びます。

- **docx から作り、出版版 PDF で補う**（初期値。PDF が必要）: Word の文字が正で、出版版 PDF（印刷所の校正を経たもの）からは
  著者校正の直し（変更履歴）と組版の違い（全角・半角・ダッシュ・引用符など）を補います。補った docx が元の docx からそれ以外に
  変わっていないことを確かめます。先に、PDF で補った docx（`巻_開始ページ_PDFで補完した原稿.docx`）を作り、それを変換します。
  - docx と PDF の違いは 3 つに分けます。
    - (A) 組版の違い: 英数字・記号の全角・半角（そのすぐ前後の PDF にない空白も消します。「理論 (ATD) に」→「理論（ATD）に」）、
      ダッシュ・ハイフン、引用符の字形・向き、英文の題目・副題・著者名・所属の大文字・小文字、Word が付ける番号の全角・半角と字形
      （「●」→「・」）。PDF に合わせ、確認は要りません（13.2）。
    - (B) 校正の直し: 「資料」→「付録」などの語句の追加・削除・置き換え。変更履歴で補います（13.1）。
    - (C) 決められない違い: 足すか消すかを PDF から決められないもの。直さず、理由を付けて 13.3 に載せ、要確認にします。
  - 13 章の構成: 13.1 PDF で補った校正の直し、13.2 組版の違い、13.3 直さなかった箇所（要確認）、13.4 Word が付ける番号、
    13.5 補った docx と PDF の照合（残っている違い）、13.6 PDF に見つからなかった段落、13.7 照合に使わなかった PDF の文字、
    13.8 補完の確かめ。
  - 補完の確かめ: 変換の最後に、補った docx が元の docx から、組版の違いと 13.1 の補った箇所以外に変わっていないことを、照合・直しとは
    別の実装で確かめます（不合格は要対応。レポートの 1 章と 13.8）。
  - 補った docx は **Word の変更履歴つき**です（作成者名は「jasme-jats（出版版 PDF による補完）」）。スタイル・書式・数式・図・注は
    そのままです。Word で開いて変更を確かめ、却下したい変更があれば、却下して保存した docx を「docx から作る」で変換し直してください。
    補った docx は、ダウンロードする `変換結果_巻_開始ページ.zip`（ノートブックは手順 8、1 画面版は「結果をダウンロード」）に入っています（コマンドラインでは出力フォルダ）。
    ファイル名は `巻_開始ページ_PDFで補完した原稿.docx` です。却下して保存した docx を同じ出力フォルダのまま「docx から作り、出版版 PDF で補う」で
    かけ直したときは、入力を壊さないよう、末尾に番号を付けた別の名前（`…_PDFで補完した原稿_2.docx`、`_3`…）で作ります（レポートに実際の名前が載ります）。
  - 直さないもの: 表のセル・別行の数式・図の中の文字・資料（付録）の見出し、URL などのリンクの文字、PDF に見つからない段落、空白だけの違い
    （PDF の空白は信頼できないため）。直すと注・引用文献などのリンクや段落の役割が変わってしまう箇所も直しません（本文の「（注1）」が
    PDF では上付きの「1）」のときなど。注の番号は、すべての注で docx のままにします）。直さなかった箇所は 13 章に理由付きで載ります。
    注番号を番号だけの上付き（「…である¹」）で書いた docx を、注番号が「1)」の形の出版版 PDF で補うときは、注番号のある段落のうち
    PDF に見つからない段落や表のセルが 1 つでもあると、ほかの段落の注のリンクが外れてしまうので、注と関係のない誤字の直しも含めて
    何も直さないことがあります（13 章に「直すと、段落の役割やリンク…」の理由で載り、XML は docx のままです。今の版の限界です）。
    PDF で補いたいときは、Word で注番号を「1)」の形に直してから変換し直すか、13 章を見て docx を手で直してください。
  - PDF のページ番号・誌名の行・柱（各ページに繰り返す誌名・著者名など）・投稿受付日など、組版で入る文字と、docx にない図・表の中の
    文字（表のセルの数字、図の中の点の名前など）は、段落の途中にあっても docx に足しません（PDF の側にこうした文字しかない位置の docx の
    文字も、消さず、置き換えません。13 章に理由付きで載ります）。足さなかった文字のうち、段落の途中にあったもの（ページ番号を除く）は、
    13 章の最後に一覧が載ります。ページの端の行にまるごと入った校正の一文なども、柱などと区別できないので
    ここに載ります。本文の一部なら、docx を手で直してから変換し直してください。PDF にだけある 20 文字以上の文字も、図の中の文字などの
    ことがあるので足しません（本文の行にかかるものは 13 章に理由付きで載ります）。13 章で PDF の文字の「⏎」は、PDF の行の変わり目です。
  - PDF の行末のハイフンと同じ位置にある docx のハイフン（self-explanation の「-」など）は、docx のままにします（行末で単語を分けた
    ハイフンか、本当のハイフンかを PDF から決められないため。docx にハイフンがなければ足しません）。PDF の行末の文字が、docx と違う
    「-」「‐」のとき（docx の「‑」〈Word の改行なしハイフン〉と PDF の「-」など）は、行の途中と同じく PDF に合わせて直します。
  - docx のダッシュ（en dash「–」、em dash「—」、水平線「―」、マイナス「−」など）と同じ位置に、PDF では行末の「-」があるとき
    （引用文献のページの範囲が「pp.11-」と「16」の 2 行に分かれるときなど）は、行の途中のダッシュの違いと同じく、PDF に合わせて
    「-」に直します（docx のダッシュは消しません）。PDF の行末の文字が何の字形か分からないとき（PDF の文字の取り出しで行末の
    ハイフンの印になるとき）は、docx のままにします。
  - PDF の中で表・図やほかの段落に分断された段落も、分かれた部分ごとに照合して直します。段落の最初・最後で、PDF にだけある文字を
    足すか、docx の文字を消すかを決められない違い（図の中の文字が本文の行につながっているかもしれないもの、段落の最後〈最初〉の
    文字とよく似た図の中の行と並べたかもしれないもの、PDF の同じ行に 2 つの段落が並び、間の文字がどちらの段落の文字か決められない
    ものなど）は、直さずに 13 章に理由付きで載せます。
  - PDF で数式など文字として読み取れない部分（PDF の文字では空白の並びになります）のすぐ隣にある違い（校正で足された、数式を含む
    語句など）は、足す文字を決められないので直さず、13 章に理由付きで載せます（13 章の表の「〓」は、PDF の欄では PDF の数式などの
    位置、docx の欄と前後の欄では docx の数式・画像です）。本文に
    必要なら、docx を手で直してから変換し直してください。
  - Word が付ける番号（自動段落番号、Word の脚注・文末脚注の番号）は docx の文字ではないので、変換のときに全角・半角と字形を PDF に合わせます
    （本文の注番号「1)」→「1）」、注の一覧「1)」→「１）」など）。PDF と照合しない段落（表のセル・囲み・別行数式）と、
    付記・謝辞・注・引用文献・資料・英文要旨の見出しの番号は、PDF に合わせず Word の形のままです。
- **docx から作る**: docx の文字のまま XML にします。PDF と違う箇所は、校正の直し（「資料」と「付録」など）を 13.1 に「要確認」として、
  組版の違い（全角・半角、ダッシュ、引用符、英文の題目などの大文字・小文字）を 13.2 に（確認は要りません）載せるだけです。PDF がまだないときや、docx が著者校正を経た最終版だと
  分かっているときに選びます。
- コマンドラインでは、`--pdf 記事.pdf` を指定すると「docx から作り、出版版 PDF で補う」、指定しないと「docx から作る」になります。
  PDF を指定して「docx から作る」にするときは `--route docx` を付けます。

## できないこと・注意点

- docx の文字は、Word で表示される文字（変更履歴をすべて承諾し、隠し文字を隠した状態）として読みます。
  - 段落記号が変更履歴で削除されている段落は、承諾した状態として次の段落とつなぎ、XML では 1 つの段落にします（見出しと本文がつながると、書式は文字のある最初の段落のものです）。
    次が表・コンテンツコントロール・セルや本文の最後などでつなげないときは、2 段落のまま出力し、レポートの 10 章に出します。
    スタイルの違う段落をつないだときは 4 章に記録します。
  - 文字スタイル・段落スタイル・既定の書式で隠し文字になっている文字も、隠して出力しません（Word の表示と同じかの判定は暫定です。レポートの 6 章に記録します）。
    この判定は暫定なので、そのような文字・画像があるときは要確認として知らせます（上の「変換レポートの見方」の要確認「スタイルの設定で
    隠し文字になっている文字を出力していません」）。Word の表示と違うときは知らせてください。隠し文字の中にあるテキストボックスの文字は、隠さずに出力します
    （隠し文字の中の画像は出力しません）。
  - 変更履歴で削除された表の行は、文字が残っていなければ読み飛ばします（6 章に記録します）。
  - 表のセルの中の改行（Shift+Enter）は、`<break/>` を補って出力します。本文・見出し・題目・著者・所属・引用文献の中の改行は、改行の文字のまま出力します。
    どれもレポートの 10 章に一覧を出し、題目・著者・所属・引用文献の改行は要確認として知らせます（J-STAGE では改行が使えない場所です。要らない改行は Word で消して変換し直してください）。
- 図・表の画像は、docx の中の画像を使わず、作業する人が出版版 PDF から用意して入れます（Word の図形やグラフで描かれた図も同じです）。画像の要る図・表の一覧
  （名前・キャプション・場所）が、レポートの 9 章と 14 章のチェックリスト、Colab の青い枠、コマンドラインの表示に出ます。
  ノートブックは手順 7「図の画像を入れる」、1 画面版は「図の画像」の欄、コマンドラインは `--images フォルダ`（ファイル名は fig03.png・図3.png・
  29_55_fig03.png のどれでもよい。画像で補える文字〈囲い文字など〉の位置の画像〈opt…〉も、その名前で入れられる。論文ごとにフォルダを分け、ほかの記事の識別子が付いた名前は入れない。名前の合わないファイルは標準エラーに出て、
  残りは入る）で、図ごとにその図の画像（PNG・JPEG・GIF）を入れると、中身を変えずに（向き・圧縮を変えずに）ZIP に入れ、XML とレポートも作り直します。
  コマンドラインは、画像の要る図・表の表（見出しは手順の「あと N 枚／全部で M 枚」）と、図の確かめの一覧（HTML）の場所を標準出力に出します。
  EMF/WMF を変換しないので、LibreOffice は要りません（`--no-metafile-conversion` はなくなりました）。
  PDF・TIFF などの画像は受け付けないので、PNG か JPEG にしてください。図の題目（「図1　…」）は XML に入っているので、画像には含めません。
- テキストボックスやグループ化した図形に入った図表（2 段組をまたぐ図など）は、図の本体とキャプションを組にして、
  Word で表示したときに図の左上の直上にある本文の段落の後に置きます。docx には表示後の位置が記録されていないため、位置を機械的に決められるもの
  （図の左上が、図形を結び付けた段落の左上にあるもの）以外は AI に判断させます。機械的に決めた図表でも、2 段組みの 2 段にまたがるもの（図形の幅が 1 段の幅の 1.3 倍より広いもの）は、AI が出版版 PDF を見て答えたときだけ、AI の答えた位置に移します（PDF を見ていない回答では Word の位置のまま。理由はレポートの 2 章）。AI による仕上げを「使わない」設定でも変換は中止しません。AI を使わないときと、AI を使っても位置が決まらなかった
  図表は、図を結び付けた段落のすぐ後ろ（その段落が箇条書き・引用の途中なら、その終わり。結び付いた段落が注や引用文献などの段落なら本文の最後）に置き、
  推奨の手順「AI で図・表の位置を合わせる」として知らせます（このまま登載することもできます）。AI が「図・表は本文より後ろ（注・引用文献・資料の中）に
  ある」と答えた図表も、本文の最後に置きます。本文の最後に置いた図表は、要確認「本文の最後に置いた図・表」にもなります（AI の答えも添えます）。
  同じ段落の後ろに図表が 2 つ以上並ぶときは、AI が答えた順に並べ、AI の答えのない図表はその後ろに図の番号順で置きます。
  置いた位置と理由はレポートの 3 章に、AI が判断した位置はレポートの 2 章と「AI判断一覧」に出ます。
  表のセルに画像とキャプションを並べた図や、画像のない図キャプションのすぐ上に置いた表（表で組んだ図）は、AI を使わなくても図として組みます。
- 引用文献・注の節や、題目・著者名・所属の段落には、画像を入れる場所を作れません。こうした段落や、XML に出力しなかった段落（冒頭の装飾など）の中に
  画像があると、その画像は XML にも ZIP にも入りません。レポートの冒頭（要対応）・9 章・14 章、Colab の赤い枠、コマンドラインの表示に
  「画像を入れる場所を作れなかった画像」として出るので、資料の図なら Word で資料を英文要旨の後ろに移し、ほかの本文に必要な画像なら、Word でその画像
  （テキストボックスなどの図形に入っているときは図形ごと）を本文の段落に移してから、変換し直してください。隠し文字の中の画像は、Word で表示されないので出力しません（レポートの 6 章に記録します）。
- 図・表を含まないテキストボックス（問題文・ヒントなどの囲み）の文字は、`<boxed-text>` として XML に出力します（Word で表示される位置が
  分かるものはその位置、分からないものは上の「位置を推定した囲み」）。図に重ねた短い注記（図の中の文字）と判断したものは、図の一部とみなして
  XML には出力せず、レポートの 6 章と 10 章の警告にだけ載せます。本文の文章なのに注記とみなされたときは、AI による仕上げで囲みに戻せます
  （依頼文に載ります）。囲みか注記か決められないものは、要確認として知らせます（上の「要確認」の説明）。
  図・表の入ったテキストボックスの中の、キャプションでない文字（出典など）は、今までどおり図の一部とみなして出力せず、要確認として知らせます。
  囲みの文字は出版版 PDF と照合しません。J-STAGE の画面で囲みがどう表示されるかは、試験登載で確かめてください。
- 引用文献・注・付記・謝辞・英文要旨の段落に結び付いた図形に入った図表は、その領域の段落にせず、「位置を決められない図表」として AI に位置を
  判断させます（AI を使わない設定では本文の最後に置き、要確認にします）。文字だけのテキストボックスは、囲みと判定したものを本文の最後に `<boxed-text>` として
  出力し、要確認にします（図の注記・決められないものは、本文のときと同じく出力しません）。
  資料の中の図形は、今までどおり資料の中に出力します。
- 同じ種類の見出し（引用文献・注・付記・謝辞・英文要旨）が 2 つある原稿と、著者名の付かない所属の段落・著者表の行がある原稿は、そのまま変換すると
  段落の文字が XML に入らなくなるので、変換を中止し、段落と Word での直し方を表示します（コマンドラインは終了コード 2。上の「変換を中止するとき」）。
  1 人の著者に所属が 2 つ以上あるときは、テンプレートの著者表のその著者の行の所属の欄に、段落を分けて並べてください。
  コマンドラインで前の変換と同じ出力フォルダ（`--out`）を指定すると、中止しても前の変換の XML・ZIP は残ります（消してから変換し直してください）。
- 注の節の中の表は、直前の注の中に出力します（表の前の「表キャプション」の段落はキャプションになります。レポートの 4 章に記録）。J-STAGE の画面で
  注の中の表がどう表示されるかは、まだ確かめていないので、プレビューで確かめてください。
- ルビ（ふりがな）は JATS 1.1 で表現できないため、親文字だけを出力します（レポートに記録）。
- 和文の論文の英文要旨は、J-STAGE の規則（「抄録(英)」には「タイトル(英)」が必要）に合わせて翻訳抄録（`<trans-abstract>`）として出力します。
  抄録の二次利用の可否（`specific-use`）は `<abstract>` にしか付けられないため、和文の論文では出力されません。
  英文の論文で使う値は `src/jasme_jats/data/jasme.toml` で設定してください（既定は「二次利用不可」）。
- DTD に合っていても J-STAGE のアップロードで弾かれる条件のうち、XML だけで判定できるもの（題目と抄録の言語の対応など）は変換時に確かめ、レポートの 12 章に出します。
- 注はテンプレートの書き方（本文に上付きの「1)」、注は「注」の節）を想定しています。本文の大きさの「（注1）」や、引用文献の後ろに置いた注の節も変換できます。Word の脚注・文末脚注の機能で書かれた注は、本文で最初に参照される順の通し番号を本誌の形式「1)」にし（Word の表示は「1」や「i」）、見出し「注」を補います（どれもレポートの 4 章・8 章に記録します）。題目・所属・引用文献の中の注の参照は、リンクにせず上付きの番号だけにします（著者名の中では番号も出しません。8 章に「なし」と出ます）。手で書いた注と Word の注が両方あって番号が重なるときは、要確認で知らせます。記号を自分で付けた文末脚注は、本文の記号は docx のまま（注へのリンクにはなりません）、番号を 1 つ使います。資料（付録）の見出しは、「資料1」「【資料１】」「付録Ⅲ」「資料2-1」「Appendix B.」などの書き方を認識します（「資料1、2は授業の記録である。」のような「。」で終わる段落や「(Appendix 1) lists ….」のような英文の文は、見出しにしません。「資料1　授業プリント。」のように「。」で終わる見出しも文とみなします。最初の資料なら、Word でその段落に見出しのスタイルを付けると資料になります（2 つ目からの資料は、AI による仕上げで直せます）。英文要旨の後ろに章・節の見出しのスタイルの段落があっても資料を始めます。どちらで始めたときも、文とみなして見出しにしなかったときも、レポートの 4 章に記録します。引用文献などの後ろに置いた資料は、資料にせず 10 章で知らせます〉。本文の上付きの指数・単位（cm²・x²・s⁻¹ など）は、注へのリンクにしません（英字・数字の直後の上付きの数字は指数とみなすので〈「図1¹」のような図・表の番号の直後は除きます〉、「Piaget¹」のような注番号もリンクしません）。本文に上付きの「1)」「注1」の形の注番号が 1 つでもある論文（表の中の上付きの「1)」も数えます）では、括弧のない番号だけの上付きの数字（「…である²」）も注にしません。また、語の中の「図1」「表1」（地図1・付表1・発表1回目など）は、図・表へのリンクにしません。リンクにしなかった箇所は、対応する注・図表があればレポートの 4 章に載ります（注番号や参照のつもりなら、AI による仕上げで直せます）。番号の書き方が想定外の注は 1 件にまとめられることがあるので、レポートの 3 章を確認してください（AI による仕上げで区切りを直せます）。
- 著者名は、姓と名の間の空白で姓と名に分けます（氏名の前後の空白は出力しません）。和文の氏名で字の間に空白を入れて揃えている
  とき（「試　験　六　郎」など）は、空白がいちばん長い所で分けます（全角の空白は半角 2 つ分の長さとして比べます）。いちばん長い空白が
  2 か所以上あって、姓と名の境目を決められないときは、論文の中の表記から推定します。手がかりは、姓だけの引用の形（「試験（2020）」
  「試験ら (2020a)」「試験・研究（2021）」「（試験，2020）」のように、姓の後ろに括弧や「，」で年が続く形。「・」の後ろは、
  氏名らしい漢字・かな・カナの 1〜4 字か英字の姓だけです。年の直後が「年」（「2019年に」）なら日付なので手がかりにせず、「中1」
  「小・中学校（2019）」「中・高（2019）」のような学校種・学年の語も手がかりにしません）で、なければ字数（3 字以上なら姓を 2 字）から
  推定します。論文の中の表記は、その著者の引用でないこともあります。推定は誤っていることがあり、字数だけの推定（手がかりがなかったとき）は
  特に誤りやすいので、その氏名があるときは「必ず確かめる」と知らせます。字の間の空白は出力しません（7 章に記録します）。氏名の後ろの注の参照と、その前の空白は、空白の数に数えません。
  空白のない和文の氏名は全体を姓として出力します。どちらも要確認で知らせるので（4 章にも記録します）、出版版 PDF の氏名と姓と名の
  境目が合っているか確かめ、違っていたら、Word で姓と名の間に空白を 1 つだけ置いて（字の間の空白は消して）保存してから変換し直して
  ください。AI による仕上げを使うと、AI が境目を確かめて指定します（AI の指定を優先します）。AI が分けた氏名も推定なので、要確認に
  「AI が境目を決めました」と残します（機械がいちばん長い空白で分けた氏名を、AI が同じ位置で確かめただけのときは、いちばん長い空白で分けた
  という知らせのままです）。英文の氏名が 1 語（空白がない）のときは、
  AI でも分けられないので 10 章の警告で知らせます。名もある氏名なら、Word で姓と名の間に空白を入れて保存してから変換し直してください。
- 図表番号は既定で `<caption>` の中に番号ごと入れます（文字を落とさないため）。`<label>` に分けたい場合はノートブックの `SPLIT_LABELS` をオンにします（番号とタイトルの間の空白 1 文字を落とし、レポートに全件記録します）。
