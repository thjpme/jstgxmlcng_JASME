# AI による補完: API キーの登録と手動モード

Colab のノートブックの手順 4「AI による補完の方法」で「API で自動実行」を選ぶときの API キーの作り方・登録のしかたと、
「手動（チャットに貼り付け）」を選ぶときの手順です。3 つの方法の違いは [USAGE.md](USAGE.md) の「AI による補完の 3 つの選び方」にあります。

## 1. API キーを作る（最初に 1 回だけ）

1. Claude Console（https://platform.claude.com/ ）にログインします。アカウントがなければ作成します。
   API の料金は、claude.ai の有料プラン（Pro など）とは別にかかります。
2. 「Settings → Billing」（https://platform.claude.com/settings/billing ）で、利用料（クレジット）を購入します。
   同じ画面で、1 か月に使う金額の上限を設定できます。使いすぎを防ぐため、上限を設定しておくことをお勧めします。
3. 「Settings → API keys」（https://platform.claude.com/settings/keys ）で **Create key** を押し、名前（例: `jasme-colab`）を付けて作成します。
4. 表示されたキー（`sk-ant-` で始まる長い文字列）をコピーします。**キーが表示されるのはこのときだけです。**
   控えずに閉じてしまったら、新しいキーを作り直してください。

## 2. Colab にキーを登録する（Google アカウントごとに 1 回）

1. 画面左端の 🔑（鍵の形）のアイコンを押します。「シークレット」という画面が開きます。
2. 「**＋ 新しいシークレットを追加**」を押します。「ノートブックからのアクセス」「名前」「値」「アクション」の欄が並んだ行が 1 行増えます。
3. 「**名前**」の欄に `ANTHROPIC_API_KEY` と入力します（大文字・小文字もこのとおりに。スペースは入れられません）。
4. 「**値**」の欄に、コピーしておいた API キー（`sk-ant-` で始まる文字列）を貼り付けます。
   入力した値は隠して表示されます。「アクション」の目のアイコンを押すと、正しく貼り付けられたか確かめられます。
5. 行の左端の「**ノートブックからのアクセス**」のスイッチを押してオンにします（✕ の表示からオンの表示に変わります）。
6. 保存ボタンはありません。入力した内容がそのまま保存されるので、シークレットの画面は閉じてかまいません。
7. ノートブックの手順 4 で「API で自動実行」を選び、手順 5 を実行します。シークレットへのアクセスを許可するか聞かれたら、許可します。

シークレットの画面にある「Gemini API キー」の欄は、Claude を使うときは関係ありません。

手順 5 で「シークレット ANTHROPIC_API_KEY を読めませんでした」と出たときは、名前の綴りと「ノートブックからのアクセス」がオンになっているかを確認してください。
キーが間違っている・無効になっているときは、変換レポートの「AI による補完」の章にエラーが表示されます。

## 3. キーを安全に扱う

- キーをノートブックのセルやメール・チャットに直接書かないでください。シークレットに保存した値は非公開で、自分と、アクセスを許可したノートブックからしか見えません。
  ノートブックを他の人と共有しても、キーは渡りません。
- キーが漏れたおそれがあるときは、Claude Console の「Settings → API keys」でそのキーを削除し、新しく作り直してください。

## 4. 料金の目安（Claude）

- 「API で自動実行」で手順 5 を実行するたびに料金がかかります（既定のモデル `claude-opus-5-5` は、入力 100 万トークンあたり 4 ドル、出力 100 万トークンあたり 20 ドル）。
- 試験に使った論文（AI への依頼文が約 4 万字）では、1 回あたりおおむね 0.3〜1 ドル程度と見込まれます（論文の長さ・図の数で変わります）。
- 実際に使ったトークン数は、変換レポートの「AI による補完」の章の最後に表示されます。
- 同じ論文を変換し直すとき（図の画像を入れ直した・書誌を直しただけで、原稿の段落と AI の設定が前の変換と同じとき）は、前の変換で得た
  AI の回答（出力フォルダの `AI回答.json`）をそのまま使い、AI を呼びません（料金はかかりません。変換レポートの「AI による仕上げ」の章に
  「前の変換で AI から得た回答…を使いました」と出ます）。Word で原稿を直した、モデルを変えたときは呼び直します。コマンドラインでは、
  `--ai-refresh` を付けると、`AI回答.json` を使わずに呼び直します。

## 5. API で使うモデルについて

- 手順 4 の「Claude のモデル（MODEL）」の既定は、このツールで動作を確かめた `claude-opus-5-5`（Claude Opus 5.5）です。
  Anthropic の発表では、このモデルの提供終了は 2027 年 9 月 22 日より前にはならない予定です
  （[モデルの提供終了の予定](https://platform.claude.com/docs/en/about-claude/model-deprecations)）。
- 将来このモデルが使えなくなった場合は、ツールが Anthropic のモデル一覧から使える最新の Opus を自動で選んでやり直し、変換レポートの「AI による補完」の章にその旨を表示します。
- はじめから最新の Opus を使いたいときは、「自動（最新の Opus）」を選びます。ただし、動作を確かめていない新しいモデルが選ばれることがあります。
- モデル名を自分で入力することもできます。使えるモデルの名前（Claude API ID）は、Anthropic のモデル一覧（[Models overview](https://platform.claude.com/docs/en/models/overview)）で確認できます。
- ChatGPT・Gemini・Sakana AI の API を使うときは、次の 6. を見てください。API キーがなくても、「手動（チャットに貼り付け）」を選べば、
  それぞれのチャット画面に依頼文を貼り付けて使えます（7.）。

## 6. ChatGPT・Gemini・Sakana AI の API を使うとき

- 「API で自動実行」は、ChatGPT（OpenAI）、Gemini（Google）、Sakana AI（Sakana Namazu・Sakana Fugu）の API にも対応しています。ただし、**推奨は Claude です**
  （このツールの AI への依頼文と動作の確認は、Claude で行っています）。
- API キーの作り方、利用料の支払い、利用上限の設定などは、**各社の案内を自分で調べて行ってください**（この説明書では説明しません）。
- 作った API キーは、上の 2. と同じ手順で Colab のシークレットに登録します。「名前」は、ChatGPT では `OPENAI_API_KEY`、
  Gemini では `GEMINI_API_KEY`（`GOOGLE_API_KEY` という名前で登録したものも使えます）、Sakana AI では `SAKANA_API_KEY` にします。
- 使うモデルの名前は、手順 4 の「Claude 以外のモデル名（OTHER_MODEL）」に自分で入力します（各社の資料で確認してください）。
  **Claude Opus と同等以上の性能のモデル（各社の最上位クラスのモデル）を推奨します。**
  性能の低いモデルでは、取りこぼしや誤った提案が増えます（誤った提案はプログラムの検証で採用されませんが、補完の効果が下がります）。
- 論文の本文は、選んだ会社（OpenAI、Google、Sakana AI）に送信されます。送信した内容の扱いは、各社の利用規約で確認してください。
  無料の利用枠では、送信した内容がサービスの改善に使われる場合があります。**Sakana AI は、既定で送信した内容をモデルの学習に使う設定です。**
  未公開の原稿を送るので、使う前に Sakana AI の管理画面（Console）の設定で、学習への利用を止めて（オプトアウトして）ください。
- 料金は各社の料金表で確認してください。使ったトークン数は、変換レポートの「AI による補完」の章の最後に表示されます。

## 7. 手動モード（チャットに貼り付け）の手順

API キーがなくても使えます。手順 4 で「手動（チャットに貼り付け）」を選んで手順 5 を実行すると、AI への依頼文が「依頼文をコピー」ボタン付きの枠で表示されます。

1. 「依頼文をコピー」を押し、claude.ai などのチャットの**新しいチャット**に貼り付けて送信します。依頼文の最初の【作業する方へ】に
   書いてあるとおり、送る前に、この論文の出版版 PDF を同じメッセージに添付してください（強く推奨。添付しなくても回答は得られますが、
   図・表の位置は Word の配置からの推定になります）。【作業する方へ】は人への案内で、AI への依頼は「# 依頼」から始まります
   （依頼文はまるごと貼り付けてかまいません）。
2. 返ってきた回答は、`json` と書かれたコードブロック（灰色の枠）1 つのはずです。枠の右上の**コピーボタン**でコピーします
   （コードブロックの外の文章が混じらず、中身がそのままコピーされます）。
3. ノートブックの手順 6 のセルの `r'''` と `'''` の間に貼り付けてから ▶ を押します。API モードと同じ検証・反映・最終チェックが行われます。

うまくいかないとき:

- 回答がコードブロックになっていない、またはアーティファクト（別の画面）として返ってきたときは、チャットで
  「依頼文の『回答の形』の見本のとおり、```json のコードブロック 1 つで出し直してください」と頼んでください。
- 読めなかったときは、何行目のどこが読めないかが表示されます。文字列が飾りの引用符（“ ”）で囲まれた回答も読み込みません
  （推測で直すと AI の指示を取り違えるおそれがあるため）。チャットで出し直しを頼んでください。
- 回答の全体が一覧（[ ] で囲んだもの）になっている、回答の項目（placements・links などの一覧）が 1 つもない、入れ子が深すぎる回答は読み込みません。チャットで「依頼文の『回答の形』の見本のとおり、```json のコードブロック 1 つで出し直してください」と頼んでください。
- 前の形式の回答（operations の一覧を持つもの）は読み込みません（「この回答は古い形式です」と表示されます）。今の依頼文を AI に渡し、返ってきた回答を貼り付けてください。
- 回答の中で段落を指すとき、AI は段落の ID と一緒に段落の先頭の 8 字（head）を書きます。先頭の文字が段落と合わない項目は、ID の書き違いのおそれがあるので使いません（2 章の「採用しなかったもの」に載ります）。
- 回答が長すぎて途中で切れていたときは、最後まで書かれていた図表の位置だけを反映し、推奨の手順「AI による仕上げ」（青い枠）の「一部」で知らせます。チャットで
  「回答が途中で切れました。同じ形式で最初から出し直してください」と頼み、新しい回答を最初から最後まで貼り付け直してください
  （続きだけを貼り付けても読めません）。
- 続けて他の論文を変換するときは、手順 6 の欄に前の論文の回答が残っています。今回の論文の依頼文を AI に渡し、返ってきた回答に貼り替えてください
  （前の論文の回答のままだと、下の依頼の番号の確かめで 1 件も反映せず、「AI による仕上げ」の「失敗」で知らせます）。1 画面版では、別の論文の
  docx に変えて変換すると回答の欄が空になります。
- 依頼文の見出しには依頼の番号（「# 依頼（依頼の番号: R-…）」）があり、AI は回答の request_id にそれを写します。ツールはこの番号で、
  どの依頼文への回答かを確かめます。
  - 別の論文への回答と、図・表・文献・注の数や並びが違う原稿（前の原稿）への回答は、1 件も反映せず、推奨の手順「AI による仕上げ」の
    「失敗」で知らせます。今の依頼文を AI に渡し、返ってきた回答を貼り付けてください。
  - 回答に request_id がないときも反映しません。AI に「request_id を含めて、同じ形式で最初から出し直してください」と頼んでください。
  - Word で誤字やスタイルだけを直した原稿には、直す前の依頼文への回答も使えます（段落の番号のずれは、段落の先頭の文字で読み替えます）。
    レポートの 2 章に「原稿を直す前の回答です」と出ます。先頭の文字で確かめられない指定は使いません。
- 原稿の構造を直す必要があるとき（同じ種類の見出しが 2 つ・著者名の付かない所属。`docs/USAGE.md` の「変換を中止するとき」）は、手動モードでも
  依頼文を作る前に変換を中止します（AI に渡す必要はありません。Word で直してから変換し直してください）。AI の回答の役割の指定で同じ形になるときは、
  その指定を使わずに変換し、レポートの 2 章の「AI の提案のうち、検証で採用しなかったもの」に理由を載せます。
