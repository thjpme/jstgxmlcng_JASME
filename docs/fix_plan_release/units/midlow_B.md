## 設計と実装

### C089: URL・DOI のリンクの範囲（文字は変えない。LinkSpec の範囲だけ）
- `linker.RE_URL`: 止める文字に和文の約物・かっこ（「．」「〈〉」「《》」「｛｝」「：」「；」「！」「？」）を足した。すべての非 ASCII では止めない
  （パーセント符号化していない IRI〈日本語のページ名など〉を途中で切ると、別のページを指す正しく見えるリンクになるため）。
- `linker._trim`: 今までの末尾の句読点・対応しない閉じかっこに加えて、閲覧した日などの語（`RE_ACCESS_TAIL`。「参照」「閲覧」「アクセス」「取得」と「した」「する」。かっこの中なら閉じかっこごと）と、
  組になる閉じかっこのない「(」「（」から後ろ（`_unclosed_open`）を、変わらなくなるまで外す。「…/a.pdf(2024.1.9参照)」は「…/a.pdf」がリンクになり、「(2024.1.9参照)」は文字のまま後ろに残る。
  組になるかっこ（「…/A_(b)」）は URL の一部のまま。
  点検 review20 の後: 閲覧した日などの語を外すのは、外した後の最後の文字が ASCII で「/」「=」「?」「#」「&」「_」「-」でないときだけ（`ACCESS_KEEP_END`。
  「…/wiki/参照」「…/wiki/文献参照」は切らない。後者は非 ASCII が残るので link_iri）。閉じていない「(」から後ろを外すのは、後ろが空・数字・非 ASCII・英語の閲覧の語
  （accessed など）で始まるときだけ（`RE_OPEN_NOTE`。数字は日付の形〈2〜4 桁の数字と「年」「.」「/」「-」、4 桁の数字で終わる形〉のときだけ。「…?q=(a」「…?q=(1」は切らない。その href は ASCII なので知らせもない。0.35.0 までと同じ）。
- `RE_DOI_PREFIXED`・`RE_DOI_BARE`: 印字できる ASCII の文字だけ（空白・「"」「<」「>」と非 ASCII で止める）。ASCII の範囲で書き、`re.I` は使わない（`re.I` では、範囲に
  U+0130・U+0131・U+017F・U+212A〈「i」「k」「s」の大文字・小文字の仲間〉も入る。点検 review20 原則 2）。接頭辞の「doi」は `[dD][oO][iI]` で書く。
- それでも href に非 ASCII が残るリンクは、推定で切らず、要確認 `link_iri`（下）で知らせる。

### C090 と C089 の残り: 要確認 `link_iri`
- `linker.href_problems(plan)`: `body_paragraphs` の段落の外部リンク（uri・ext-link・pub-id。同じ LinkSpec の続くアトムを 1 つのリンク）のうち、リンク先に非 ASCII があるもの（種類 iri）と、
  http・https・mailto・ftp 以外のリンク先（種類 scheme。file:・javascript:・パソコンの中のパスなど）を `HrefProblem` で返す。リンク先の値は書き換えず、リンクも外さない。
- `report._link_iri_action`: 件数・先頭 5 件（`LINK_IRI_SHOWN`。段落 ID・場所・リンクの文字・リンク先・種類）と、種類ごとの直し方（Word で直して変換し直す。
  画面の操作は `step('docx')`）。点検 review20 の後: XML の xlink:href を手で直す案は外した（ZIP の XML は変わらず、変換し直すと消える）。iri の直し方は「Word で URL の文字だけを選び、［挿入］の［リンク］で正しいアドレスを入れる」。引用文献の中の、URL の文字と同じリンク先の Word のハイパーリンクは、`Linker.word_spans` に範囲を覚え、`urls()` の URL・DOI をその終わりまでに縮める（すぐ後ろが非 ASCII の文字のときだけ。点検 review20 の 2 回目。今までは範囲を捨てて正規表現に任せていたので、Word で直しても後ろの文字が入った）。`actions()` では `_float_ref_action` の次。key を 1 つにまとめた（指示のとおり）。

### C111: 英文の文の間の全角の「，」「．」（route pdf）
- `pdfmatch.PdfCheck.spaced_after`（`_classify` が入れる）: 全角・半角を直す文字（width の位置）のうち、PDF ではすぐ後ろに英文の単語の間の空白（`_pdf_space`）があり、docx では空白なしに
  次の文字が続くもの。
- `pdfdocx.hold(fixes, texts, spaced)` の (b2): 全角の「，」「．」→「,」「.」の kind width の直しで、docx のすぐ後ろが空白でない半角の英数字（`RE_NOSPACE_NEXT`）、かつ `spaced_after` にあるものに
  `NOSPACE_REASON`（全角のまま。空白は足さない）。最初の `spread_reasons` の後に付け、もう一度 `spread_reasons` を通すので、それを根拠にした空白の削除（`Fix.needs`）も直さない（片方向。
  空白の削除を止めても根拠でない直しは止まらない）。一続きの規則の始まりにはしない（`start` が `NOSPACE_REASON` を除く）。`plan_fixes` は変えていない（「PDF に合わせるなら何を変えるか」のまま）。
- 13.2: `skipped_typeset` のうち `NOSPACE_REASON` のものを、「直せない位置にあるもの」と別の行（`report.SILENT_NOSPACE`）で数える。補完の確かめ（`fidelity.verify_supplement`）は変えていない。
- 指示の条件（docx のすぐ後ろが空白でない半角の英数字）に、PDF ではすぐ後ろに空白があることを足した。足さないと、PDF でも空白のない「pp．45」→「pp.45」の形の直しまで止まるため。
  実際の 46 docx では、docx の条件に当たる直しはすべて PDF でもすぐ後ろに空白があり、足した条件で外れたものは 0（両方の条件で同じ 58 か所）。
