## 2. 設計

方針: 3 つとも「構造を推定する直し」ではない。C022 は PDF の文字の読み方、C048 は読み取りの規則の共有、C050 はツール自身の (1) の直しの誤りをやめる直しで、
どれも docx に足す文字は増えず（C048 は今まで止めていた (1) を当てるだけ）、新しい Action は足さない（「警告は最小限」）。知らせだけにする案は 2.5。

### 2.1 C050: PDF に見える区切りの空白を消さない（構造は変えない。知らせない）

起きる条件: docx の半角の空白が、全角・半角を直す文字（または Word が付ける番号）のすぐ隣にあり、PDF のその位置の前に、同じ行の空白があって、`_pdf_space` が「和文・全角の文字の隣」として見かけの空白とみなすとき。

直し方:
- `pdfmatch.py` の `_pdf_space`（3158〜3168 行）の隣に、新しい関数 `_seen_space(st, k) -> bool` と定数 `SPACED_PUNCT`（字形の中に空きのある全角の約物「（）［］｛｝〈〉《》「」『』【】〔〕，．、。：；・！？」）を置く:
  `st.newline_before[k]` が偽で `st.space_before[k]` が真で、かつ (a) `st.wide_space[k]`（PDF の同じ行に全角の空白）か、(b) `st.chars[k - 1]` と `st.chars[k]` がどちらも `SPACED_PUNCT` にないとき真。
- `_classify` の `drops` の判定（3066 行）を `if not _pdf_space(st, pk) and not _seen_space(st, pk):` にする。3061〜3064 行の注に、残す条件と理由（見かけの空白は全角の約物の字形の中の空き）を書き足す。
- `_pdf_space` 自体は変えない（ほかの用途〈違いの PDF の文字の空白の戻し、`_report_regions` など〉がある）。

原則との関係: docx の文字を消す直しが減るだけで、足す・置き換える直しは増えない。残った空白は docx の文字。`Emitter.span()`・除外・Action は変わらない。
補完の確かめ（`fidelity.verify_supplement`）は削除が減るだけなので変えない。PDF から docx に内容を足さない。

足すテスト（`tests/test_pdfmatch.py`。架空。`owl_convert` の形で通しの変換）:
1. 「記録は表1 架空の集計にまとめた。」と PDF「記録は表１　架空の集計にまとめた。」→ 補った docx・XML とも「表１ 架空の集計」（全角化は当たり、空白は残る）。補完の確かめは合格。
2. 「『架空読本A 改訂版』」と PDF「『架空読本Ａ 改訂版』」→「『架空読本Ａ 改訂版』」。
3. 対照: 「鳥の声は (架空の) 記録」と PDF「鳥の声は（架空の）記録」→ 空白は消える（全角の約物の隣）。
4. 対照: PDF に空白がない「表１架空の集計」→ 今までどおり消す。
5. 対照: PDF の空白が改行だけ → 今までどおり消す。
6. `_seen_space` の単体テスト（`PdfStream` を手で組む。全角の空白・半角の空白・約物の隣・改行）。
既存の `drops` 系のテスト（`drop_basis`・`needs` の連動）が変わらないことを確かめる。

回帰で変わる見込み（`reg_c050.log` で確かめた）: ルート2 の XML だけが、data11（3 変種とも）6 か所、data13（3 変種とも）2、data28 2、data10・data15（3 変種とも）・data24 各 1 で、空白が 1 つ戻る。
状態・不変性・最終・補完の確かめ・DTD・知らせの key の差は 0。ルート1 は同じ。

危険と避ける条件:
- pdfium は字間が広がった行（両端そろえ）でも空白を足すことがある。全角の英数字と和文の間に、本物でない空白が出た位置では、docx の空白が残る（docx の文字なので原則には反しない。PDF よりわずかに空くだけ）。46 docx の (b) の 5 か所はすべて本物だった。
  不安なら (a) の全角の空白だけにする（決めること D1-2）。
- 全角の約物の隣は今までどおり消すので、「Owl（2012）to」の形（docx「Owl (2012) to」）は残る。PDF の見た目（全角のかっこの字形の中の空き）と同じなので、勧めは残す（D1-1）。

### 2.2 C048: 図形のある段落も表記を直す（読み取りの規則を共有する。知らせない）

起きる条件: 表記の違い (1) がある段落に、`w:drawing`・`w:pict`・`w:object` が（ランの直下に、またはランの中の `mc:AlternateContent` の採る側に）あるとき。浮動の図形に限らず、行内の画像も。

直し方（FIELD_TEST の勧めどおり、規則を二重に持たない）:
1. `ooxml.py` に、図形 1 つが段落に置くアトムの元の並びを返す純粋な関数 `graphic_atoms(el) -> list` を置き、`docx_reader._in_textbox`（996〜1003 行）を `ooxml.in_textbox` に移す。
   規則は今の `docx_reader._graphic`（710〜803 行）のまま: `w:drawing` はテキストボックスの外の `pic:pic` の並び。なければ、テキストボックスがない・グループ・キャンバス・chart のとき `[el]`（図形だけの画像 1 つ）、
